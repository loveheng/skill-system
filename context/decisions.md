### [2026-10-07] todos 两级落点：域级 todos 文件 + 全局兜底 (src: 用户)

**场景/痛点**：todos 与 devlog 同为域挂靠，却用「单文件分节」模拟目录模型——同一域归属概念存在双路实现。实际使用已绷紧：goodshare 43 条未结挤在单文件（>30 洗盘线早已触发）、出现非标准手搓节「goodshare · 暂缓/候」（规范没有停车场，用户自造）；shiguang 仅 2 条待办仍出现行格式违规（手搓编辑全局文件的漂移在极小规模也发生）；域内消费（::next 候选/恢复/::done 清零）都要 sed 抽节，多 epic 共写同一文件无写隔离。

**可选方案（含否决理由）**：
- A 仅工具化不改布局（todos 机械写入工具）：解决写漂移，但不解决域内聚、防膨胀局部化、::done 归档随迁——域内自治诉求永远差一口气，将来重搬时工具还得再动一遍。否决为终态，但工具化本身并入最终方案。
- B 全部域文件化（misc 也建域文件）：破坏「散修零成本」（随手一条备忘要先建文件）、epic 文件数膨胀多为空文件噪音。否决，misc 留全局兜底节。
- C 两级模型（采纳）：域内 `epics/<名>/todos.md`（按需创建）+ 全局 `todos.md`（misc 散修 / 跨域 / 项目级兜底），配套 todos 工具与路由规则写死。

**最终决定**：C 四件套一次落地，不拆步——① 域级文件按需创建（mount-init 不预建空骨架，首条域内待办落盘时创建）；② 全局文件只留 `## misc` 末节（跨域 `(风险)`/`(block)`、项目级、S3 PATCH 债、副作用高危转化、散修杂项）；③ 路由规则写死进 memo-collector §0（域内 = 该 epic 可独立解决的行动项；全局 = 上述兜底类；拆解结构与理由仍归挂载文档 blueprint，todos 只收一行式行动项，防双写）；④ 新增全局工具 `todos`（add/done/rm/move/list）为机械件，`::todos` 全量 = 机械聚合视图。done.md 维持全局单文件（完成台账是跨域历史）。

**AI 洞察**：§0 原单文件论证（读成本：全局一览低频、无恢复必读压力）在真实数据面前反转——写漂移与膨胀是比读成本更高频的痛点；「全局一览」降级为工具聚合一条命令后，读成本论据消失。挂靠模型从此只有一种实现（目录），分节模拟退役。
