### [2026-10-15] 跨库只读评估-移交协议：AI 读评估、用户自行操作目标库 (src: 用户)

**场景/痛点**：AI 在当前仓发现底层/外部公共库接口「不顺手」时倾向顺手直接改目标库——跨仓写入破坏独立发布周期（无法原子提交）、静默损坏未进上下文的下游调用方、绕过 CODEOWNERS 审核边界、违背契约优先原则。全盘禁止跨库又导致坐井观天，诊断质量下降。

**可选方案（含否决理由）**：
- A 完全隔离（AI 禁止接触目标库）：过严，排查复杂链路 Bug 失去全链路只读感知，否决。
- B 提案式落盘（AI 在目标库开 PR 草稿/写 patch 文件到目标库路径）：仍由 AI 触碰目标库写路径，审批门需额外机制且 AI 快照可能落后于目标库 HEAD，否决。
- C 只读评估-移交（采纳）：读/写二分——① AI 任意跨仓**只读**；② 产出**移交件**（固定格式：目标库、结论、依据、建议操作含 Expand-Contract 拆分建议、风险与未看到的信息、快照 commit），只落当前仓或聊天框；③ 目标库**任何写入**（clone/commit/PR/issue）由用户本人执行，AI 严禁代行；④ 用户操作后 AI 可只读复查闭环。

**最终决定**：采纳 C 作为默认协议。配套两条：豁免档——用户**逐次显式授权**某目标库可写时解除该库写入禁令（授权不写进默认规则，防个人小库场景逼出「先越权后补授权」坏习惯）；灰区——依赖升级（改本仓锁文件）不算跨库写入，但禁盲升 major。条款写死于 `skills/dev-loop/SKILL.md` §2。

**AI 洞察**：此模型的核心资产是**移交件格式**而非禁令本身——禁令约束行为，格式保证用户拿到的东西能独立操作；「依据/风险」字段为强制项，逼 AI 声明其只读快照**没看到什么**，比结论本身更重要。评估结论基于快照，移交件必须标注快照 commit，用户操作前以目标库 HEAD 为准。

### [2026-10-15] 轻量级防御演进：反事实白名单探针与内核锁原语 (src: 用户)

**场景/痛点**：四深水区缺口评估（递归压缩失真 / 僵尸白名单 / 并发会话 / 上下文赤字）发现体系数据面领先展示面与裁决面——多数缺口不是「没做」而是「已计算未展示 / 已计数未裁决」。同时评估中两个候选方案（session 级 PID 锁、自动 worktree）与体系自身宪法红线及失败模式画像自相矛盾，需决策层否决以防实现期漂移。

**可选方案（含否决理由）**：
- A session 级 PID 锁（所有权锁）：否决——flock 由内核在进程死亡时自动释放（无陈旧态/无 TTL/无心跳）；PID 文件在终端关闭后锁文件永存，陈旧锁失败模式比它防的竞态更糟，且直接对抗恢复模型（重置后新会话接管是核心路径）。
- B mount-init 自动创建 git worktree：否决——`git worktree add` 是 git 写操作，体系宪法写死「Agent 严禁代跑 git 写、生成不执行」；且 context/ 随仓库版本化，两 worktree = 两份 context/ = 记忆脑裂，破坏单记忆库不变量。
- C 轻量防御（采纳）：① 白名单 = 反事实存活探针（删此行会不会多报 ≥1 条？否 → 失效 → 入 --md/--json，裁决留 audit 层）；② 并发 = flock 包断点写临界区 + mkdir 原子性替代「检查后创建」+ worktree 仅生成建议命令（不执行）；③ 上下文 = 暴露 resident%（已计算未展示）+ 校准 WINDOW_MAX 分母。

**最终决定**：采纳 C，本轮落地 1–3 项——① dscan/uscan/ascan 白名单逐行归因 + 反事实存活报告（工具契约 0/1/2 不变，⚠ 裁决置 ::audit 层，ascan 不因失效行改 exit code 防干净审计被标 FAIL）；② panel/ctx-ratio 输出 resident% + 按宿主模型校准 WINDOW_MAX；③ devlog bp 包 flock + mount-init mkdir 原子化 + 并行期输出 worktree 建议命令。关键原则：**凡写保护必配 liveness，但白名单与规则不对称**——白名单行主动遮蔽发现，失效即盲区，可反事实 GC（删了只多报不漏报）；未触发护栏规则是保险非盲区，禁零触发 GC（等于退保），规则陈旧走 ::audit 第 ⑩ 项 + 月度人审。

**AI 洞察**：① 缺口一与二同构——任何写保护存储（不变量/白名单/lessons/decisions）缺 liveness 探针时，写保护从「防漂移」退化为「锁死腐烂」，保护越强腐朽越危险，「凡写保护必配 liveness」应进 lessons；② 593% 非「窗口占 593%」而是「长会话峰值单次请求输入侧 ÷ 固定 200k 基准」，真实裁决是「本会话该归并+重置」（⚠ 已发出）；输出 token 是此后每轮的常驻输入（每轮全量重发），故「极简回复」本质是输入预算管理而非省 token；③ 本轮实施全是「把既有信号接线到展示/裁决层」（resident 已算、suppressed 已计、并行行已出），零新增子系统，契合「零新增容器、机械件只搬运」哲学。

### [2026-10-07] todos 两级落点：域级 todos 文件 + 全局兜底 (src: 用户)

**场景/痛点**：todos 与 devlog 同为域挂靠，却用「单文件分节」模拟目录模型——同一域归属概念存在双路实现。实际使用已绷紧：goodshare 43 条未结挤在单文件（>30 洗盘线早已触发）、出现非标准手搓节「goodshare · 暂缓/候」（规范没有停车场，用户自造）；shiguang 仅 2 条待办仍出现行格式违规（手搓编辑全局文件的漂移在极小规模也发生）；域内消费（::next 候选/恢复/::done 清零）都要 sed 抽节，多 epic 共写同一文件无写隔离。

**可选方案（含否决理由）**：
- A 仅工具化不改布局（todos 机械写入工具）：解决写漂移，但不解决域内聚、防膨胀局部化、::done 归档随迁——域内自治诉求永远差一口气，将来重搬时工具还得再动一遍。否决为终态，但工具化本身并入最终方案。
- B 全部域文件化（misc 也建域文件）：破坏「散修零成本」（随手一条备忘要先建文件）、epic 文件数膨胀多为空文件噪音。否决，misc 留全局兜底节。
- C 两级模型（采纳）：域内 `epics/<名>/todos.md`（按需创建）+ 全局 `todos.md`（misc 散修 / 跨域 / 项目级兜底），配套 todos 工具与路由规则写死。

**最终决定**：C 四件套一次落地，不拆步——① 域级文件按需创建（mount-init 不预建空骨架，首条域内待办落盘时创建）；② 全局文件只留 `## misc` 末节（跨域 `(风险)`/`(block)`、项目级、S3 PATCH 债、副作用高危转化、散修杂项）；③ 路由规则写死进 memo-collector §0（域内 = 该 epic 可独立解决的行动项；全局 = 上述兜底类；拆解结构与理由仍归挂载文档 blueprint，todos 只收一行式行动项，防双写）；④ 新增全局工具 `todos`（add/done/rm/move/list）为机械件，`::todos` 全量 = 机械聚合视图。done.md 维持全局单文件（完成台账是跨域历史）。

**AI 洞察**：§0 原单文件论证（读成本：全局一览低频、无恢复必读压力）在真实数据面前反转——写漂移与膨胀是比读成本更高频的痛点；「全局一览」降级为工具聚合一条命令后，读成本论据消失。挂靠模型从此只有一种实现（目录），分节模拟退役。
