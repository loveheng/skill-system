# project-index · 通用索引机制

本 skill 只承载机制，零项目数据。索引数据 = 各项目仓库内的 project-local skill，随仓库版本化、随代码一起演进。

## 架构与加载

- 索引落点（固定约定）：`<repo>/.agents/skills/<repo-name>-index/SKILL.md`，frontmatter `name` 与目录同名。
- 判定当前项目：取工作区根目录名 `<repo-name>`。Zed 会自动发现 project-local skill（新会话生效）；未自动加载时，直接读上述路径。
- 索引不存在时：按 `template.md` 引导用户创建——先只登记域级锚点，够用再细化，禁止一次性铺满。
- 归属表定位不到时，才对相关根目录做全量 grep / find_path。

## 表格式规范

索引正文固定包含前三节，可选节按项目需要增删：

1. **归属表**（核心）：`领域 | 覆盖功能 | 代码落点 | 文档落点`。代码落点 = 包/目录/固定单文件锚点（+ 展开命令）；文档落点 = `docs/<域>/` 或具体文档，无则填 —。前端类项目可按需改造列（如 store/服务/视图分列）。跨域隐式契约在行内加 `联动: <域>（一句话为何）`，只兑机器查不出的语义耦合。
2. **业务别名映射**：业务口语、别名、关键词 → 领域，平铺列表。**失配驱动登记**：检索真的脱靶一次才补一个词，不预罗列同义词；脚本归组用的代码命名关键词（如 GROUPS）与查表用的业务别名分开登记。
3. **用法**：先查表 → 展开命令或以该路径为 include_pattern 限定搜索 → 展开结果只用于当前任务，禁止写回索引 → 定位不到才全量搜索。
4. 可选节：变更落点顺序、实时脚本用法、验证命令、维护约定、关联 skill。

锚点原则：只存低频变化的锚点（领域包、子包、目录、固定单文件）；类清单/文件明细靠展开命令或实时脚本现场获取，防止索引腐化。

## 调阅协议（两级展开，Token 经济学）

- **L1（静态）**：加载索引锚点表，按关键词/业务别名定位到 1~2 个目标域。
- **L2（动态）**：只对目标域触发展开命令（find / map:features -- <域> / grep 限定路径），展开该域实时文件清单。
- **兑底**：L1 定位不到、L2 落空时才全量 grep / find_path；L2 结果禁止写回索引。
- **防膨胀预算**：索引正文软上限 ~80 行；超限优先扩收集脚本，不扩表。

## 维护协议

- **可推导的不维护，不可推导的才登记**：路径/命名/脚本能算出来的（域归属、类清单、文件触点、frontmatter 字段）靠收集器现场 derive；机器算不出的（关键词、意图性归属、一句话定位）才平时维护——改哪个功能/文档，顺手登记哪一行，不批量。
- **禁止为「以后收集」给文件新增元数据字段**：元数据只有和产生它的编辑动作绑定才不烂（如 frontmatter status/updated）；需要专门跑一趟补的字段最终都是假数据。确需扩充 frontmatter，先修订该项目文档规范再动手。
- **联动标记只兑机器查不出的隐式契约**：「谁 import 谁」是可推导的（护栏/测试/grep 能查），不人工登记；能用测试或护栏守护的优先加护栏（Modulith 模式），标记只兑语义耦合（如缓存 self-invocation、双通道共用快照格式）。
- 新增领域/大功能 → 归属表加一行；**禁止把类名清单、文件触点清单写进表**。
- **脚本优先**：项目有实时扫描/收集脚本（feature-map、doc-index-lint 一类）时，脚本输出是实时事实源，表与脚本冲突以脚本为准；表只存脚本覆盖不到的锚点。
- 域拆分/合并/迁移 → 改索引同时检查 `docs/README.md` 域头与引用了旧域名的其他 skill/docs。
- 索引随功能 PR 一起改，不走单独文档流程。

## 边界（防双源漂移）

- 本索引：功能 → 代码/文档**域级归属**的唯一事实源。
- `docs/README.md`：文档结构索引（域 → 文档 → 一句话定位），不承载功能归属。
- dev-loop 的 memory/devlog：过程记忆，与索引无关。
- 规范类 skill（写法/文档规范/工作流/构建）：只放规则，不放归属表。
