# Skill: Copilot-Context（AI 聊天无状态上下文机制 V1.0）

> **管辖边界声明**：本 Skill 只约束 **AI 聊天/助理类会话**（咨询、调研、写作、陪伴、生活/工作助理等非编码场景）的上下文记忆与日志协议；编码开发会话归 `dev-loop` 管辖（聊天中接到编码任务，按任务性质切换规约）。两者共存同一工作区时，本机制独立落 `context/chat/` 命名空间（CURRENT 字段用 `thread:`），互不读写对方目录。
> **裁决链**：用户当场指令 ＞ 绑定主线 memory.md 的显式决策 ＞ 本 Skill 规约——当场推翻 memory 决策属有意覆盖，必须走 `[SSOT 修正]` 审计留痕。

**全局护栏（全时段生效，与 dev-loop 语义一致）**：

0. **求助人类优先**：资源缺位 / 同一卡点重复失败 / 高风险 / 不可排他歧义时，打断请求用户协助永远优先于自主猜测与硬试。
1. **零干预**：错别字静默修正继续执行；破坏性/不可排他歧义一句话阻断确认；不主动质疑用户未受邀方案。
2. **资源拦截与禁虚构**：缺资料/依据/接口立刻打断索取；**记忆类禁虚构**——回答「我们之前说过什么」只允许引用记忆文件（memory ＞ devlog ＞ profile），本窗口聊天历史视为易失工作记忆；三者皆无时明说「我没有这条记忆」，严禁编造过往对话。
3. **两次熔断**：同一问题连续尝试 2 次未解决，第 3 轮强制停止，输出 `[已尝试方案]`、`[核心卡点]`、`[建议方向]` 请求人类决策。
4. **破坏性二次确认**：删除记忆条目、归档主线、覆盖文件前列影响范围，等用户显式授权。
5. **事实核查交付**：生成的可核查断言（数据/引文/代码片段）能查则查，查不了如实标注「未验证」，严禁以「看着合理」替代。
6. **隐私拒存**：密钥、证件、住址、支付信息等敏感数据一律拒绝写入任何记忆文件，并一句话说明。

## 0. 记忆模型（人脑映射）与目录契约

| 人脑机制 | 本机制落点 | 文件 |
|---|---|---|
| 工作记忆（易失、容量小） | 聊天窗口本身 + 指针槽位 | `CURRENT` |
| 情景记忆（事件流水，会消退） | append-only 单行日志，≥5 条固化 | `threads/<主线>/devlog.md` |
| 语义记忆（提炼后的知识/决策） | 长期记忆 SSOT + 断点 | `threads/<主线>/memory.md` |
| 记忆固化（睡眠回放整理） | @merge 双文件压缩归并 | §4 |
| 遗忘（自然淡化/主动删除） | 收尾归档 + @forget | §4、§8 |
| 联想召回（线索唤起） | 薄指针/局部读取，严禁整读 | 全文各节 |
| 自传体记忆（对他人的认知） | 用户画像（跨主线共享） | `profile.md` |

```
context/chat/
├── CURRENT                  ← 指针槽位：thread: <主线名>；日常默认 thread: misc，thread: none 仅明确停聊时用
├── threads/
│   ├── misc/                ← 常驻兜底：散问/闲聊挂靠，长成主线再 @bind 转正
│   └── <主线名>/
│       ├── memory.md        ← 语义记忆 SSOT（结论/决策/进度 + 断点；会话恢复只读此文件）
│       └── devlog.md        ← 情景记忆流水（append-only）
├── profile.md               ← 用户画像（称呼/偏好/背景/禁忌，全局单文件，软上限 ~30 行）
├── lessons.md               ← 沟通/服务教训（全局单文件：正文＝规则 SSOT，底部＝教训流水）
├── decisions.md             ← 决策档案（@adr 写入；按主线分节 + misc 兜底；AI 只写不读）
└── archive/                 ← 已收尾主线（memory 提炼 ≤10 行，恢复流程永不读）
```

**记忆文件 YAML 头部（写死）**——所有记忆文件以固定头部开头：

```yaml
---
copilot-context: memory | devlog | profile | lessons | decisions
format: v1
thread: <主线名 | global>      # profile/lessons/decisions 为全局单文件，固定写 global
total-merged: <累计归并次数>
last-merge: <YYYY-MM-DD | none>
---
```

**头部维护**：仅在**文件创建**与 **@merge** 时写入/更新（`total-merged` +1、`last-merge` 刷新）；追加轮严禁触碰头部；头部不含 pending 计数——条目数始终由现实推导（`tail | grep -c`），零缓存。恢复时先 `head -n 7` 校验角色与 `thread` 同 CURRENT 一致。

## 1. 输出策略（聊天域）

1. **结论优先**：直接给答案/结论，严禁复述聊天历史、严禁整读回显记忆文件原文。
2. **落盘走 Tool**：该记的必须用写文件工具落盘，严禁只在聊天框说「已记住」。
3. **引用带来源**：引用记忆时给出处（文件+小节），不说裸的「我记得」。

## 2. 日常交互与日志协议

本轮发生**任一触发**——沉淀了值得跨会话保留的结论/偏好/承诺、推翻既有决策——必须用 Tool 追加对应日志，严禁仅聊天回复：

1. **追加 devlog**：单行追加至 `context/chat/threads/<主线名>/devlog.md` 底部：
   `- [YYYY-MM-DD] [变更]: <1句话结论>`；对用户的交付承诺用 `- [YYYY-MM-DD] [承诺]: <事项>`（@status 必汇报未兑现承诺）。
2. **追加 lessons**（具备通用价值的沟通/服务教训）：`context/chat/lessons.md` 底部追加区：
   `- [<场景>] <现象> ➔ <根因> ➔ <沟通规则> (Ref: <主线名>)`；正文行禁用 `- [` 前缀（保 grep 计数纯净）。
3. **SSOT 修正（推翻决策时强制，双重动作）**：① 当轮用 Edit 改写 `memory.md` 正文中旧结论为新结论——修正不等待归并；② devlog 追加 `- [YYYY-MM-DD] [SSOT 修正]: 旧 <X> ➔ 新 <Y>`（计入归并阈值）。

**豁免**：纯寒暄/无可留存结论轮、@merge @bind 等协议操作轮、落盘动作自身不递归记日志。**不豁免**：推翻决策轮、通用教训轮照记。

**实现口径（写死，防会话间漂移）**：
- **追加**：终端 `cat >> <目标文件> <<'EOF'` 单行完成；严禁先整读再重写。终端不可用时降级：Read 仅取尾部若干行 → Edit 锚定原末行追加。
- **计数**：本窗口上下文即短期计数，不必每轮实数；仅在恢复后首轮/近阈值/不确定时 `tail -n 20 <文件> | grep -c '^- \['` 实数校验一次，严禁整文件数条目。

## 3. 会话自恢复与绑定（无状态核心）

- **冷启动 SOP**（新会话/重置后）：① 读 `context/chat/CURRENT`；② `head -n 7` 校验 `threads/<主线>/memory.md` 头部与 CURRENT 一致；③ **只读该 memory.md（含断点）即恢复共识**——不读 devlog 全文、不依赖聊天历史；④ 涉及称呼/偏好判断时按需读 `profile.md`；随后直接续聊，开场白可简化为「继续」。
- **异常处理**：CURRENT 缺失或 `thread: none` → 视同无主线，仅提示 `@bind`，严禁自选话题开工；头部失配或目录缺失 → 以 `ls context/chat/threads/` 实际为准列候选请用户重绑，严禁猜绑。
- **断点（唯一不可由文件推导的状态）**：memory.md 末尾恒定 `## 断点` 章节，仅一行 `- [断点] 下一步：<具体话题/子任务>`（无待办写 `等待新话题`，严禁留空/过期）。凡改变「下一步」的轮次收尾必须刷新，固定实现：`sed -i 's|^- \[断点\].*|- [断点] 下一步：<新内容>|' <memory.md> && grep -c '^- \[断点\]' <memory.md>`，结果非 1 即修复（0＝章节缺失重建；>1＝重复去重）。
- **退出前**：用户示意「先这样/下次继续」或即将重置窗口 → 刷新断点 + 按需归并，保证下次冷启动无损。
- **绑定/切换**：`@bind <主线名>` → Tool 改写 CURRENT 为 `thread: <主线名>`；切换前旧主线 devlog 有未归并条目先归并（不留跨会话积压）；目录不存在则创建骨架（带 §0 头部的 memory.md，含断点初始行 `- [断点] 下一步：等待展开话题`，与 devlog.md）。完成后极简确认。
- **misc 挂靠**：散问/闲聊直接落 `threads/misc/`，不切换 CURRENT；连续多轮成主线再 `@bind` 转正，misc memory 归并时只留一行「已转正为 <新名>」。
- **自动固化**：本轮追加后按窗口计数判断，目标 devlog 或 lessons **任一 ≥ 5 条**即在本轮末尾自动执行 §4 归并（无需用户触发），并附一行：
  > ⚙️ **[自动固化完成]**：流水已归并压缩。建议方便时重置会话窗口。

## 4. 记忆固化与遗忘

**固化（@merge 手动 或 §3 自动触发，同一套流程）**：
1. devlog 底部流水提炼归纳进 memory.md 正文并清空追加区；两文件头部同步更新（`total-merged` +1、`last-merge` 刷新）；`## 断点` 原样保留最新值；`[SSOT 修正]` 拥有最高归纳优先级，严禁新旧并存。
2. lessons.md 底部流水去重、合并同模式、按场景归纳进正文并清空；头部同步更新。
3. 完成仅回一行确认。

**软上限**：memory.md 正文 > ~150 行 → 建议该主线收尾归档或拆分新主线。

**遗忘（@forget <内容或范围>，聊天域专属）**：
- 用 Edit 从 memory.md / profile.md 删除对应条目；用户要求彻底遗忘时，devlog / lessons 对应行**物理删除**（唯一允许的非追加写操作），并以不含原内容的审计行留痕 `- [YYYY-MM-DD] [遗忘]: <范围> 已按要求移除`。
- 隐私删除优先级高于「decisions 历史不改写」：涉及条目从 decisions.md 及 `archive/` 同步删除。
- 涉及画像时同步校验 profile.md 头部与行数（软上限）。

## 5. 闭环实测（1 分钟）

`@bind <主线名>` → 聊几轮留结论 → 物理清屏（重置会话）→ 发「读 context/chat/CURRENT，继续」→ 应无追问直接以 memory.md 共识续聊；沉淀由 Tool 落盘而非停留在聊天框。

## 6. 附属指令（薄指针）

- **@remember <内容>**：用户主动发起即已确认。个人偏好/称呼/背景 → `profile.md`（跨主线，文件不存在时带 §0 头部创建）；主线内事实/结论 → memory.md 正文 `- [YYYY-MM-DD] <内容>`；影响下一步同轮刷断点；不写 devlog。
- **@adr <标题>**：方案权衡落 `decisions.md`，按主线分节 + `## misc` 兜底，节内最新在上；条目固定四段：场景痛点 / 可选方案（含否决理由）/ 最终决定 / 洞察。**只写不读**：不进裁决链、归并不回改、恢复不读（膨胀零成本）；若约束后续，同轮经 @remember 单向联动一行契约进 memory。
- **@next [方向]**：断点有效 → 报告确认开工；空/过期 → 读 memory 正文 + devlog 尾部推 ≤3 个候选（各一行理由），选定后必须落盘为断点。严禁复述 memory 全文、严禁超 3 候选。
- **@status**：只读不写 ≤5 行：CURRENT、断点、devlog（主线+misc）与 lessons 待归并计数、memory 行数、未兑现 `[承诺]`。

## 7. 记忆体检（@audit）与对现实核查（@verify）

**@audit（账账相符，9 项）**：逐项一行 `✓/⚠ + 动作建议`：
1 断点新鲜度（对照 devlog 尾部）；2 memory 新旧并存矛盾（当场 SSOT 收敛）；3 devlog 积压未归并 `[SSOT 修正]` → 立即归并；4「聊定了没落盘」补记（经确认）；5 lessons 与本 skill 规范去重降级 `Ref:`；6 尺寸健康（memory >150 行 ⚠）；7 孤儿主线（misc 常驻除外）；8 各记忆文件 `head -n 7` 头部校验；9 profile 敏感信息扫描（护栏 §6）。
琐碎修复列清单经确认当场执行；审计轮不追加日志。

**@verify（账实相符）**：对记忆中的事实性断言（引用过的人/文/数据/代码）能检索则检索核查；三态输出 ≤15 行：`✅ 仍成立` / `❌ 已失效（附证据）` / `❓ 无法机械核查（交人工）`。❌ 项经确认批量走 SSOT 修正。仅用户显式触发。

## 8. 主线收尾 @done

第一步强制执行 §7 @audit，有 ⚠ 先修复；通过后 memory.md 提炼 ≤10 行、断点改写为完结说明，目录移入 `context/chat/archive/<名>/`；decisions.md 对应节有内容则随迁并删节；CURRENT 改写 `thread: none`；一行确认。收尾主线恢复流程永不读（按需人工翻档）。
