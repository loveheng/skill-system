# Dev-Loop REFERENCE（参考件：§5-§8 执行细则）

> **分层**：本文件 = dev-loop 的**细则层**——§5/§6/§7/§8 执行口径的唯一事实源；SKILL.md = 摘要层（§0-§4 全时段热路径规约 + §5-§9 摘要与指针）。外部「dev-loop §N」引用：N∈{5,6,7,8} 的细则在本文对应节，其余在 SKILL.md。**按需加载**：执行对应指令/审计/收尾/接入验收时读对应节，日常会话不加载本文。修改细则只改本文，严禁回填 SKILL.md 复述（§9 薄指针铁律）。

## 5. 实测闭环验证 (1 分钟，dev-init 接入时跑一次)

`::file <名>` → 确认骨架创建与 CURRENT 写入 → 重置窗口 → 发「读 context/CURRENT，开始：[子任务]」→ 成功标准：不追问绑定、直接按 memory 断点开工；代码变更日志落 devlog 而非聊天框。

## 6. 附属指令流程 (Manual Ops)

- **`::remember <事实>`（人工记忆入口）**：结论**直接写入 memory.md 正文**（用户主动发起即视为已确认）；若影响下一步，同轮刷新断点。**不写 devlog**——已直入 SSOT。
- **`::adr <标题>`（决策洞察档案）**：本窗口敲定的方案权衡以多行条目落 `context/decisions.md`——**按 epic 分节 + `## misc` 常驻兜底**（节不存在时锚 `## misc` 上方插入，`## misc` 恒最后一节；节内最新在上）。条目格式（写死）：`### [YYYY-MM-DD] <标题> (src: ai | 用户)` + 四段——场景/痛点、可选方案（含否决理由）、最终决定、AI 洞察。**定位护栏**：decisions.md 是历史档案非权威——不进裁决链（memory 冲突以 memory 为准）、SSOT 修正与归并不回改（历史不改写）、恢复不读（AI 只写不读）。落盘同轮二选一显式留痕：约束后续工作 → 经 `::remember` 写入 memory；不约束 → 尾标 `（不约束后续工作）`——严禁不表态（::audit 第 9 项对账兜底）。
- **`::next [方向]`（断点规划）**：① 断点明确且未过期 → 报告内容，确认是否开工；② 断点为空/`等待拆解`/已过期 → 读 memory 正文 + `tail -n 20` devlog，推导候选子任务（**≤3 个，各一行理由**），用户选定或默认第一项 → 按 §3 口径写入断点并校验 → 开工。**严禁复述 memory 全文、严禁超出 3 候选**——规划结果必须落盘为断点，否则本轮规划等于白聊。
- **`::board`（任务看板，多任务并行选择入口）**：跑 `toolbox run panel --board` 取逐任务表（`<epic> ｜ 最后活动 <日期> ｜ 断点：<内容>`，当前绑定标 ▶，misc 标「常驻」，archive/ 不列，按最后活动降序），按下方「面板判读协议」渲染，**末尾固定附一行跨 AI 恢复咒语**：`其他 AI/工具：读 context/epics/<任务名>/memory.md 按断点继续`。只读不写；用户选定后走 `::bind` 正常绑定流程。
- **`::status`（运行态快照）**：一条调用链返回——CURRENT 内容、断点行、devlog（绑定 epic 与 misc 两处）与 lessons 待归并计数（`tail -n 20 | grep -c '^- \['`）、`wc -l` memory 行数。**只读不写，输出 ≤5 行**。
- **`::help`（面板入口，求助第一句）**：跑 `toolbox run panel` 取事实块（绑定/断点/任务活动/计数），按下方「面板判读协议」渲染四区——**我在哪 / 现状 / 建议动作 / 按意图命令速查**（速查一行分组即可，全量命令清单含含义仅用户显式索要时经 `toolbox run cmds` 收集输出，cmds 缺失降级读 COMMANDS.md）；新会话 / 跨 IDE 求助入口；排错协作时附一行「人类侧排错说明：`problem-triage/manual.md`」。
- **面板判读协议（::help / ::board 共用，写死）**：① **事实以脚本为唯一来源**——跑 `toolbox run panel` 后严禁再 grep/读文件重复取证；脚本缺失（未入池环境）才降级手推（board 用 ls+grep 现场推导口径）；panel 自身故障（exit 2）时可改跑轻量 `toolbox run ctx-status`（仅 ::status 数据面）；② 事实块**原样嵌入**，数字/日期严禁改写或凭印象修正，数据可疑重跑脚本，不手改；③ **建议动作由 AI 结合本窗口语境自产**（≤3 条，有信号才写、无信号不凑数）——机建议位暂留空，稳定复现的建议按 §8 收敛复盘口径逐步固化进脚本；④ 追问按需 `toolbox run panel --deep <epic>` 单点取数（债面追问用 `panel --debt`：标记分布 top 文件 + 白名单 + 上次体检时效），不做全量深挖；⑤ 常态回复 ≤10 行；面板只读只建议，执行仍走 §9 触发纪律；⑥ **字段同步**：panel 输出字段增删的当轮，同步依赖它的卡模板（§3 绑定卡）——panel 改字段与卡模板改字段是同一轮义务。

## 7. 审计与质检 (Audit)

**触发**：① `::audit` 手动；② `::done` 第一步**强制执行**；③ 建议时机：多机同步/分支切换后、久别重置恢复后。**机械项可选预填**：先跑 `toolbox run ctx-audit --root <项目根>`（委托 context-lint 代跑机械项，人判项标 ❓ 交 AI 补判），按其结果逐项输出 ✓/⚠——清单语义以本节为唯一事实源，脚本仅是执行器；脚本缺失时照常手工逐项。

**清单（12 项）**（逐项一行输出 `✓ / ⚠ + 动作建议`）：

1. **断点新鲜度**：`grep -n '^- \[断点\]' memory.md` 对照 devlog 尾部——已被完成工作超越即 ⚠，转 `::next` 重写；
2. **新旧并存**：通读 memory 正文，同主题残留多条矛盾结论即 ⚠，按 `[SSOT 修正]` 优先级当场收敛；
3. **devlog 积压高价值项**：devlog 存在未归并的 `[SSOT 修正]` 即 ⚠，**立即执行 §4 归并**（堵重置复活缺口）；
4. **记忆补记审查**：对照本窗口结论与 memory 正文——「聊定了但没落盘」的决策即 ⚠，经确认按 `::remember` 口径补写（记忆库自查生长，对应插件的回合内记忆审查，此处为手动低频触发）；
5. **lessons 与规范去重**：对照现有规范 skill 清单，已被覆盖的正文条目降级为一行 `Ref:`；
6. **尺寸健康**：`wc -l` 三文件，memory 正文 >150 行 ⚠ 建议收尾或拆分（§4 软上限）；
7. **孤儿 epic**：`ls context/epics/` 对照 CURRENT 与各 devlog 修改时间，长期未动者提示 `::done` 或确认搁置（**misc 为常驻挂靠，不算孤儿**）；
8. **头部校验**：`head -n 7` 各记忆文件，字段缺失/角色与目录不符即 ⚠；
9. **指针抽查**：grep 各薄指针（COMMANDS.md 命令手册、dev-guide §3 命令速查、项目索引关联行）与各 memory.md 挂载行（路径存在、非 deprecated 墓碑；机械项由 audit 钩 context-lint 挂载面代跑）的锚点串是否在目标文件真实存在——不存在即 ⚠，当场修指针；改过其他 skill 节号/节名后必查（引用方含 COMMANDS.md），例行审计抽查 2~3 条控成本。另含 **decisions↔memory 契约对账**：decisions.md 各节最新 1~2 条在对应 epic 的 memory 正文有无约束型契约行——缺失即 ⚠，经确认补 `::remember`（::adr 单向联动无写入校验，此处兜底）。project-local skill 对代码现实的锚点存在性（路径/命令/类名 FQN）可跑 `toolbox run skill-verify` 代跑（机械半边，语义核实留 AI）。
10. **skill 卫生抽查（事实指针化）**：规范类 skill 正文严禁自带易漂移事实（模块结构/领域清单/编译命令/依赖版本号/环境限制），一律指针到项目事实源（workflow 类 skill、项目索引），grep 抽查疑似事实锚点，正文自带非指针出处即 ⚠ 当场改写；description 是路由触发信号非正文，只留项目锚点+技术栈+高频症状关键词，细节沉正文；description 机械上限 550 字符（ctx-audit 项 J 检查，超限即 ⚠ 压缩——加载器拒载边界的实测值，该检查属加载器行为微操，加载器升级后与本句一同退役）。新增 skill 或改过事实性段落后必查，例行抽查 2~3 条控成本。
11. **toolbox 巡检（agent-toolbox）**：toolbox 已初始化（`~/.agents/toolbox/` 存在）时执行 `toolbox run-hooks audit --quiet`——**以退出码判定**：exit 0 = ✓，exit 1 = ⚠（`--quiet` 静默一切输出，只看退出码；需 FAIL/ERROR 明细时再跑不带 `--quiet` 的 `toolbox run-hooks audit`，或 `toolbox run cl` 裸跑），按 memo-collector 口径转 `风险` 待办；空池/未初始化直接 ✓ 跳过；
12. **验证缺口抽查**：grep devlog 尾部最近 2~3 条 `[变更]` 行是否各有同日 `[验证]` 账本行——[变更] 无 [验证]、或 [验证] 写「未执行」无理由即 ⚠，补验证或确认补因；人工抽查（机械化待办，口径同第 9/10 项）。

**修复纪律**：琐碎修复（归并积压、补记、降级 Ref、重写断点）列清单经确认当场执行；结构性修复（拆分、归档）转 `::done` 或用户决策。**审计轮不追加任何日志**（豁免规则适用）。

**`::verify <epic|lessons|all>`（账实对账）**：上方十二项是**账账相符**（记忆与 skill 文档内部一致）；verify 验**账实相符**（记忆 vs 代码现实）——裁决链已把 memory 抬到最高权威，无验真机制即裸奔。
- **范围钳制**：仅验可机械定位的断言（引用具体类名/路径/属性/阈值/开关的结论）；抽象理由/偏好一律标 ❓ 交人工，不猜测。
- **三态输出**（≤15 行）：`✅ 仍成立` / `❌ 已失效（附代码证据行）` / `❓ 无法机械验证`。
- **修复路径**：❌ 项提议**批量 `[SSOT 修正]`**（memory / lessons 各走 §2 对应通道），经用户确认落盘；lessons 失效规则优先修——过期教训会误导未来每一轮排错。
- **建议时机**：里程碑收尾、久别重开、`lessons.md` 归并出新规则后（趁热验真）、起疑时。仅用户显式触发。

## 8. epic 收尾 (Closure)

- **`::done`**（**misc 常驻，不适用收尾**）：第一步**强制执行 §7 审计，存在 ⚠ 项即中止收尾、先修复**；通过后执行**收敛复盘**（升舱后输出一行度量，见下）；随后**待办先处置清零**（memo-collector §4：完成流转/转全局/删除，经确认，`epics/<名>/todos.md` 随目录归档）；再将 memory.md 提炼为 **≤10 行结论块**（保留头部与 `## 断点` 改写为完结说明），目录移入 `context/archive/<名>/`，`decisions.md` 中该 epic 节若有条目则整体移入 `context/archive/<名>/decisions.md` 并删除该节，`CURRENT` 改写为 `epic: none`，一行回复确认。收尾后该 epic 退出活跃集，恢复流程永不再读它（按需人工翻档）。

**收敛复盘（::done 内置，升舱 L2→L3）**：收尾时逐项核对——① lessons 正文中已被验证多次、表述稳定的条目 → 提议固化进规范/事实源 skill（原条目降级一行 `Ref:`，对齐 §7 第 5 项口径）；② devlog/待办中同类澄清 ≥2 次的约束 → 按 memo-collector「咒语」行固化信号提议升级事实源；③ todos 中 `[long]` 条目按 memo-collector §4 重评；④ ::verify 近期 ❌ 项确认已批量 SSOT 修正。全部走「提议 → 用户确认 → 落位」，AI 不静默改写 skill。收尾回复附一行**收敛度量**：`收敛: +N 固化 / M 待定 → 事实源`（N=本轮升舱条数，M=仍留 L2 的条数）——跨 epic 观察趋势，固化递增、待定递减即体系在收敛。
