## 2. 日常交互细则 (SKILL §2 下沉)

- **快车道（全文）**：影响面小且可逆——**≤3 文件**、不涉 schema/命令协议/公共契约/**数据迁移**、意图明确无歧义——的小改散修走快车道：免评估/复述轮、免决策台账、文档（ui-spec 等）攒批补写，仅保留 devlog `[变更]/[验证]` 与断点刷新；验证按分级执行。**连续同类小修默认沿用快车道**（无需逐轮重判，仅文件数/契约面变化时重判）。用户显式要求方案对齐/评估时照做（用户指令优先）；任一判据不满足即回标准流程；大需求/结构重构照旧走 dev-guide。
- **副作用标记（全文）**：写码遇到「实现未实证」或「猜测性兜底（空 catch / 只记日志 / 返回默认值）」时按 `ai-sideeffect-guard §1` 留 `// UNCERTAIN:` / `// DEGRADE:` 标记（带日期指纹，DEGRADE 须在兜底前打 `[DEGRADE] <场景key>` 日志）——标记不落 devlog、只随代码生存；四工具扫描与高危项处置见 `ai-sideeffect-guard §2`/§4（高危按 memo-collector 口径转 `风险` 待办）。**阻断边界（写死）**：扫描 `exit 1` 语义是「需人读报告」而非阻断；被阻断的永远只是「逾期未处置的标记」（Epic 收尾结算时未清零且未转办），严禁为消除报告而删标记（删标判据见 ai-sideeffect-guard §6）。
- **测试写保护与验证外生（全文）**：跑修码循环前先识别核心测试（`tests/core/`、`tests/golden/` 或 project-index 声明的基准测试）为**只读契约**——本会话 diff 命中即判本轮失败并告警：严禁修改/放宽断言、加 Mock 绕行或删用例使红灯变绿，唯一出路是回滚改动重写实现（验证判定权外生于执行者，Goodhart 防线；口径 = `context/lessons.md`「测试外生性」节）。**反向探针（变异检查）仅在 Solidify 模式**（solution-admission 双轴判定）且涉及核心逻辑时叠加，日常不跑——机械件 = `toolbox run mscan --files <改动源码> --test-cmd "<测试命令>"`（变异前先验基线全绿，存活变异即测试盲区；用法以脚本 `--help` 为准）。
- **公共接口变更 Expand-Contract（全文）**：重命名/签名变更**严禁原地突变**——① Expand：新增接口与新实现并存、旧接口保留、全量测试跑通；② 分批迁移调用方；③ Contract：单开一个 commit 移除旧接口。风险断言用「接口变更显式声明于 devlog `[变更]` 行 + 单轮含可运行验证」，**不设行数硬熔断**（行数是风险的最差代理变量——机械重命名 800 行零风险，40 行权限改动可能致命）。
- **跨库只读评估-移交协议（全文）**：涉及当前仓之外的代码库时——① AI 限于**只读评估**（任意跨仓读：源码/契约/CI/调用方清单）；② 产出**移交件**（结论/依据/建议操作/风险/快照 commit，落在当前仓或聊天框，格式见 `context/decisions.md` 2026-10-15 ADR）；③ 目标库的**任何写入**（clone/commit/PR/issue）一律由用户本人执行，AI 严禁代行——用户**逐次显式授权**可豁免该目标库（不写进默认规则）；④ 用户操作完成后 AI 只读复查闭环。依赖升级（改本仓锁文件）不算跨库写入，但禁盲升 major。
- **提问预算（写死，护栏 0 具体化）**：确认提问按预算执行——① 同类确认合并（同主题多小项一次问完）；② 复述确认型一律合并抛；③ 已附默认建议的决策点，用户回「同意默认」即整批通过，严禁逐条重述追问；④ 单轮裁决点 >4 个先按影响面收敛（小项并入默认建议）或分批（先 4 后续批），**严禁整清单倾倒**；⑤ 严禁为免责/留痕而问（能自证的不问，落 devlog 即是留痕）。提问稀缺性 = 确认有效性。
- **多决策点确认台账（全文）**：审计/方案/规划轮一次产出 **≥2 个需用户独立裁决的决策点**时，严禁「部分作答 + 催开工」让未决项悬空。**触发时机自执行（写死）**：产出决策点的**同一轮回复内**完成「登记 + 抛出第 1 问」——回复结构固定为「决策点清单正文 → 末尾登记台账（写文件）→ 紧接着抛出 **[1/N]** 第一问（附背景+默认建议）」；严禁只出清单说「请逐条确认」把动作交还用户，严禁等用户先回复才登记。流程：
  1. **登记**：全部决策点当轮落 `context/pending-confirm.md`（头部 `---` / `confirm: pending` / `format: v1` / `---`；条目行 `- [ ] [YYYY-MM-DD] <编号> <一句话问题>（不定则<后果>）`；单 epic 平铺即可，**多 epic 并行期间必须按 epic 分节**，编号节内自编）；台账随 git 提交。
  2. **引导（分级确认）**：**裁决型**（互斥选项/大影响/有依赖）逐项串行，一次只抛 1 个、等答案再抛下一个（严禁自答）；**复述确认型**（仅对齐理解）可同轮合并抛。两类混杂时拆开：复述型合并前置、裁决型接着串行。每个决策点附**背景 + 默认建议**（可「同意默认」低负担推进）；裁决型无依赖时按影响面从小到大；工具支持时用结构化选择题。
  3. **部分确认**：已确认项**即时生效落盘**；未决项挂起——**大动作严禁开工**（Schema/契约/接口签名/结构重建/跨文件大面积改动），仅允许无争议取证与小修；每次回复显式列「未确认 N 项：<编号>」并继续引导。
  4. **确认完毕**：全部确认后综合分析（冲突按裁决链收敛、方案定稿），决策一次落盘，条目清零（文件保留复用）。
  5. **可见性**：台账非空时 `::status` 附一行挂起提示；`::done` 硬前置——未清零禁止收尾。
  6. **手动拆分 `::confirm`**：AI 漏走台账流程时，用户发 `::confirm` → AI 补登记全部决策点 → 按分级口径从 `[1/N]` 开始确认；`::confirm <事项>` 带参数时仅登记该事项并立即抛问。
- **lessons 录入与归并（全文，2026-10-20 四段式升舱，源=goodhub-workflow 通用化）**：格式四段显式标签（现象/根因/处置/回归），一段一行禁无标签长文本——现象段放报错关键字/堆栈特征（保 grep 精准命中），根因写语言/运行时/平台机制本质，处置写解法/命令/修改点，回归写**回归钉子**（测试路径如 `test/xxx_test.dart`「撤修复即红」/机械规则编号 arch-guard R#/明确代码约束）。**三不记**（负面清单）：①临时网络/环境偶发抖动（无复现价值）②情绪与破案流水账（只留技术因果）③无法落地的泛泛建议（「注意并发安全」类）。**Inbox 闭环**：新坑先落底部流水区（禁直接插正文，正文只收已审条目）；epic 收官/发版前必须清零流水区；**归并门禁（写死）**：缺回归段的条目须补钉子或写明机械规则编号，否则不得进正文——只写文档不挂钉，换人照踩。存量 `➔` 旧格式条目被 touch 或归并时按四段式归一，不专门立项迁移。
- **收尾 Git 指令建议（全文）**：Diff 轮收尾附 git 指令建议代码块——`git add <文件清单>`（含本轮落盘的 context/ 记忆文件）+ `git commit -m "<一句话>"`（措辞参照本轮 devlog 行），块首标注「建议指令，未执行」；**严禁代跑任何 git 写操作**；分支级操作仅用户明示时生成；无 Diff 轮不生成。部署属项目池脚本职责。
- **豁免规则（全文）**：以下轮次**禁止追加任何日志**——① 未产出可留存结论的纯咨询/排错轮；② 执行 `::merge`、`::bind` 等协议操作轮；③ 仅维护 context/ 文档本身的轮（含日志追加自身，防递归）。**不受豁免**：通用价值 Bug → Lesson；推翻决策 → SSOT 修正。
- **实现口径（全文）**：
  - **追加**：优先 `toolbox run devlog <change|verify|note|lesson> <epic> <文本>`（单行构造/格式防呆/幂等去重内聚，`--json` 预检不落盘、`--self-test` 自测）——toolbox 缺失时降级 `cat >> <目标文件> <<'EOF'` 单行追加；**严禁先整读再重写**（成本随文件线性变贵）。终端不可用时降级 Read 尾部 → Edit 锚定原末行。日志行内避免 `${...}` 字面量（静态扫描拒）。
  - **断点刷新**：优先 `toolbox run devlog bp <epic> <文本>`（单趟替换+去重+章节缺失重建+恒 1 行校验）——缺失时降级 sed：`sed -i 's|^- \[断点\].*|- [断点] 下一步：<新内容>|' <memory.md> && grep -c '^- \[断点\]' <memory.md>`（sed 匹配零行会**静默成功**，必须 grep 校验，**非 1 即异常**：0=章节缺失→重建；>1=重复→去重保留最新；特殊字符改用 Edit 锚定）。
  - **记账单一事实源**：进度事实**只追加 devlog**；memory 正文仅 ①归并 ②`::remember` ③SSOT 修正 三通道，断点 bp 是 memory 唯一日常写入点——严禁每轮双写 devlog+memory（双写绕过归并去重，memory 单向膨胀）。同一文件同一轮只用一种编辑工具（Edit 或 sed 二选一，混用触发文件状态校验失败返工）。
  - **计数（低频校验）**：本窗口上下文即短期计数，不必每轮实数；仅 ①恢复后首轮 ②近阈值 ③长窗口/不确定时 `tail -n 20 <文件> | grep -c '^- \['` 实数一次，严禁整文件 Read 数条目。**量化探测**：`toolbox run ctx-ratio`（总量%+RCR 双阈值+冷却锁，fail-open）——命中（exit 1）且 devlog 非空 → 按 SKILL §3 自动归并；n/a=数据源不可得，严禁凭体感替代机械探测。

## 3. 恢复与绑定细则 (SKILL §3 下沉)

- **状态恢复（全文）**：读 CURRENT → 只读 `memory.md` 恢复，不读 devlog、不依赖对话历史（先 `head -n 7` 校验角色/epic 与 CURRENT 一致）。**排查交接例外（写死）**：memory 读取后对绑定 epic 的 devlog 执行 `tail -n 20 | grep '\[排查交接\]'`——命中即续读该尾部并按交接单（problem-triage §3.1）续上排查，未命中仍不读 devlog。**台账联动**：`pending-confirm.md` 有未清条目 → 开场附一行挂起提示并优先引导确认，清零前大动作冻结。CURRENT 为 `epic: none` 或缺失（新机器 clone 常态）→ 视同无活跃 epic，仅提示 `::file` 绑定；epic 目录不存在或头部失配 → 以 `ls context/epics/` 实际目录列候选，严禁猜绑。
- **绑定卡字段口径**：① **域**：dev；② **类型**：CURRENT=misc → 散修（快车道默认），非 misc → epic 主线（大需求建议加载 dev-guide），用户首句显式声明时按声明标注；③ **挂载**：▶ 绑定 epic 与其 memory/devlog 状态对，含 CURRENT 一致性核对（失配提示重绑，并行纪律 ④）；④ **任务行**：panel 任务活动表原样带上，切换走 `::board`；⑤ **状态**：断点 + 待决（>0 注明大动作冻结）+ 待归并 + 债（U/D/P 粗计数 = UNCERTAIN/DEGRADE/PATCH 标记数，非零建议 `panel --debt` 或 ai-sideeffect-guard §2 扫描；粗计数不含白名单过滤，0 ≠ 无隐患）+ ctx（panel 注入利用率——⚠ 命中按 SKILL §3 自动归并处置，n/a fail-open）+ 并行（panel「并行:」行在场时必含「恢复请点名任务」——禁裸奔「继续」默认开工）。
- **绑定与切换（全文）**：`::file`/`::bind <名>`（忽略路径后缀只取名）机械件统一 `toolbox run mount-init`——切换/续绑 `--current-only --epic <名>`，完整挂载 `--epic <名> --doc <文档>`：骨架创建（memory.md 含 §0 头部 + `## 断点` 初始行 `等待拆解`、devlog.md）、CURRENT 改写、切换前置（旧 epic 未归并先 §4 归并）与防覆盖由脚本机械拦截，**Agent 严禁手拼骨架**；脚本不可用才降级手工（同口径）。完成后极简确认，附一行形态提示（大需求建议 dev-guide；散修挂 misc 不推流程）。裸 `::file` 只列候选与当前绑定，不写文件。
- **文档挂载纪律（全文）**：正式 epic 必须挂底子文档——`::bind` 先跑 `toolbox run panel --mounts` 取候选+挂载对照（`deprecated` 墓碑不可挂；▶已挂=已有 epic，续绑或维护态重开），**epic 名 = 文档 slug**，memory 正文首部加 `- [挂载] <路径>`；候选空/不合适 → 亮牌先建底子文档再挂载（初稿提炼自**真实需求/设计内容**，严禁占位文案，**任务拆解清单严禁作为文档主体**——拆解归域内 `todos.md`；冷 bind 走反向采访），一次确认「建文档 + 建 epic」；**候选空且暂无真实设计内容 → 不建文档装拆解，仅绑定 epic，memory 挂载行指向域内 `todos.md`**（待办文件作过渡锚点，正式文档具备后升级指向）。选定后 `toolbox run mount-init --epic <名> --doc <文档>`（候选空加 `--create-doc`，首稿仍由 AI 本轮提炼落盘）——slug 一致/墓碑/重复挂载/切换前置由脚本拦截。**内容/状态分工**：底子文档 = 内容 SSOT（需求/设计/定稿即写即落，方案权衡走 ::adr），memory 只记状态与指针，严禁抄文档内容进 memory；**任务拆解清单归域内 `todos.md`，严禁写入底子文档充当挂载内容（无正式文档→不建文档装拆解，memory 挂载行指向域内 `todos.md`，正式文档具备后升级指向）**；misc 不挂载；存量 epic 缺挂载行不强制补（::audit 提示级）。**维护态（写死，目录不搬）**：epic 永驻 `context/epics/<名>/`，维护状态编码在 memory 头部 YAML——`state: maintenance`（`::done` 收尾由 `toolbox run devlog close <名> <完结说明>` 机械写入：state 标记 + 断点改「已完结：<说明>」+ CURRENT → epic: none）。同名功能继续开发/维护时**严禁另起新 epic**，重开 = `toolbox run devlog reopen <名>`（清 state 标记 + 断点回「等待拆解」+ CURRENT 指回）后 `::bind <名>` 续绑——devlog 与文档 `## 决策日志` 时间线物理延续，零快照零搬家。panel/board 对维护态 epic 标 `(维护)`（不参与并行信号、孤儿检测豁免）；**写护栏（机械）**：close 后 devlog 追加（change/verify/note）与断点刷新（bp）一律被拒（先 reopen），防收尾后惯性写入落错状态；恢复流程对维护态 epic 照常可读（它就在 epics/）。`context/archive/` 仅收**真退役**的功能（人工确认后移入，恢复流程永不读）；被退役 epic 挂过的文档再次挂载时 mount-init 会提示其已归档。
- **杂项挂靠 misc（全文）**：散修统一挂 `context/epics/misc/`，日志落 `misc/devlog.md`，不切换 CURRENT；CURRENT 日常默认 misc；散修长成大功能（连续多轮）→ `::bind <新名>` 转正（挂载纪律同上），misc memory 归并时只留一行「已转正为 <新名>」，日志不搬家；misc 断点恒为「等待散修任务」。
- **并行窗口纪律（全文，写死）**：CURRENT 是全项目单指针，多窗口并行按**一窗口一 epic** 隔离：① 每窗开工即 `::bind` 到本窗口主战场；② 并行窗口绑不同 epic，**同 epic 严禁双窗口同时写**（devlog 交错、断点互相覆盖）；③ 窗口内插入其他 epic 成规模工作前先切绑（零星散修挂 misc 不算混轮，连续多轮按转正口径）；③b **临时绑定（写死，防并行临时任务日志错位）**：窗口内需短促处理另一 epic（临时修复/看一眼/补一条日志）时，用 `toolbox run mount-init --temp --epic <名>` 切入——原绑定自动记入 CURRENT 第二行 `base:`，CURRENT 指向临时 epic，日志/归并全部正确落位；完事后 `toolbox run mount-init --restore` 恢复基础绑定（临时 epic 有未归并日志先 ::merge，切换前置拦截）。临时态在 panel 绑定行显式标注（`临时绑定，基础: <名>——完事 mount-init --restore`），**恢复前严禁丢弃/覆盖 CURRENT**；禁止嵌套临时绑定（已有 base 行先 --restore）。判定口径：连续多轮或要写码 → 正经 `::bind` 切绑；一问一答即走 → `--temp`。④ 并行期恢复后「继续」前核对 CURRENT 与本窗口一致，不符先 `::bind`（panel「并行:」行是机械触发信号）；⑤ 并行改同一批代码文件建议分支/worktree 隔离（命令模板见 panel，仅建议；worktree 的 context/ 是独立副本，记忆写入须回主仓防脑裂）；⑥ **越界失败自动暂停（写死）**：测试/构建失败且归因落在会话边界之外——失败文件 ∉ 本会话 diff（`git status --short`/`diff --name-only`）且与本人改动无因果链——**立即暂停**：严禁修改边界外文件（含「顺手修绿」），devlog 记 `[note]` 暂停行 + 断点刷新「等待用户指令：<失败摘要>」，输出三要素（失败摘要/归因证据/建议方向）后等待；仅用户显式授权方可继续。归因存疑不适用本条，走护栏 3 熔断；边界归属查 project-index 与 `::board`；单窗口同理。
- **自动重构（全文）**：日志追加完成后以上下文短期计数判断近阈值（恢复后首轮/长窗口按 §2 实现口径实数校验），**绑定 epic devlog（含 misc）与 lessons.md 任一 ≥5 条**，或 `ctx-ratio` 命中（exit 1）且 devlog 非空——满足任一在本轮末尾对该目标 epic 自动执行 §4 双文件压缩（无需用户触发），归并后 `ctx-ratio --mark-merged` 落冷却锁（默认 45 分钟防震荡）。**排错豁免（写死）**：护栏 3 熔断激活或 problem-triage 排查进行中时，ctx-ratio 命中只附一行提示、不自动归并（报错上下文不得被归并切断）；devlog 为空命中仅提示。执行后附注：⚙️ **[自动重构完成]**：追加日志已归零压缩（阈值触发）。建议方便时 Cmd+R / Ctrl+R 重置窗口。
- **开场环境检查（全文）**：shim `~/.local/bin/toolbox` 或 `~/.agents/toolbox/` 存在时，开场读 CURRENT 前先 `toolbox run-hooks bootstrap --quiet`：exit 0 静默继续；非 0 严禁阻塞恢复，仅附一行 ⚠（FAIL 明细按 memo-collector 口径转 `风险` 待办；需明细裸跑不带 `--quiet`）。未初始化环境跳过。ZCode 用户级开场协议已内嵌本钩子——同窗口不重复执行。

## 4. 归并细则 (SKILL §4 下沉)

- **决策过程归档（写死，归并与 ::done 共用前置步）**：双文件压缩/收尾清空 devlog 之前，先执行 `toolbox run dlog <epic>`——脚本机械化把 devlog 决策类条目（`[决策]`/`[SSOT 修正]`，`--tag` 可扩展）原文复制进目标专节（尾部专节、升序追加、同文行幂等去重、专节缺失自动创建）：**有挂载** → 挂载底子文档 `## 决策日志` 专节；**无挂载**（散修/misc/未挂载 epic）→ 降级 `context/misc-decisions.md` 的 epic 节（misc 即常驻 `## misc` 节，新节插在 `## misc` 之前保持其恒最后；该文件是机械归档专用，与 `::adr` 的正式 ADR 档案 `decisions.md` 语义分离、互不写入）。脚本缺失时降级 AI 手工：仅提炼**决策/权衡类**条目（[SSOT 修正]、推翻旧结论、否决备选方案类），条目格式 `- [YYYY-MM-DD] <一句话结论>（否决: <备选及理由>，可选）`；已写进文档设计正文的内容不重复抄，只留一行指针；纯过程性 [变更]/[验证] 行不进决策日志。**此步完成后才允许清空 devlog 追加区**。**去重契约（写死，归并/收尾清账共用）**：同一决策内容在「文档决策日志 / misc-decisions.md / memory 结论块」三落点**只沉淀一次**——dlog 以同文行幂等去重保证文档侧不重复；memory 提炼时对已入决策日志的条目只留一行指针（`Ref: <文档路径> ## 决策日志`），严禁整条重抄；收尾清账（`devlog clear`）必须在三落点全部完成后执行——清掉的是原始流水，沉淀不随之消失。复盘只读聚合：`toolbox run dlog collect`（`--tag` 可扩展）——三段输出 [未归档]（各 epic devlog 内决策行 = 归并欠账信号）/ [已归档-文档] / [已归档-杂项]（misc-decisions.md），只读不落盘，`--json` 给计数结论；供 `::done` 收敛复盘、`::audit` 记忆补记审查与 `::next` 推导消费。
- **极简回复格式**（自动触发为附注一行）：*"已完成 `<大功能名>` 记忆归并（devlog → memory.md）与 `lessons.md` 重构，追加日志已归零压缩。请按 Cmd+R / Ctrl+R 重置窗口。"*
- **git 冲突面**：append-only 的 devlog 合并无痛；memory.md / lessons.md 为编辑型文件，多机同时归并必然冲突且发生在提炼后正文上——单人多机需「切换机器前 commit」纪律，团队协作为已知取舍。context/ 整体入 git（仅 CURRENT gitignore），自动压缩可回溯。**过程流水保留口径（写死）**：归并清空后，非决策类 [变更]/[验证] 原文不进工作区，历史浏览一律 `git log -p -- context/`（决策类原文已由 dlog 归档进「## 决策日志」/misc-decisions.md，无需翻 git）——「保留全量靠 git、工作区只放活信息」是显式取舍非缺口；回溯有效性以 context/ 及时 commit 为前提。
- **软上限**：memory.md 正文超 ~150 行时考虑该 epic 收尾进维护态或拆分（恢复成本随正文上升）。
- **归并事故回滚（灾难恢复纪律）**：归并或记忆写入导致 memory/lessons 质量断崖下跌时，严禁 Agent 自行重写修复——`git checkout -- <文件>` 恢复最近提交版本，报告事故经过，由人工微调补记（前提：context/ 除 CURRENT 全量入 git；devlog append-only 一般无需回滚）。

## 5. 实测闭环验证 (1 分钟，dev-init 接入时跑一次)

`::file <名>` → 确认骨架创建与 CURRENT 写入 → 重置窗口 → 发「读 context/CURRENT，开始：[子任务]」→ 成功标准：不追问绑定、直接按 memory 断点开工；代码变更日志落 devlog 而非聊天框。

## 6. 附属指令流程 (Manual Ops)

- **`::remember <事实>`（人工记忆入口）**：结论**直接写入 memory.md 正文**（用户主动发起即视为已确认）；若影响下一步，同轮刷新断点。**不写 devlog**——已直入 SSOT。
- **`::adr <标题>`（决策洞察档案）**：本窗口敲定的方案权衡以多行条目落 `context/decisions.md`——**按 epic 分节 + `## misc` 常驻兜底**（节不存在时锚 `## misc` 上方插入，`## misc` 恒最后一节；节内最新在上）。条目格式（写死）：`### [YYYY-MM-DD] <标题> (src: ai | 用户)` + 四段——场景/痛点、可选方案（含否决理由）、最终决定、AI 洞察。**定位护栏**：decisions.md 是历史档案非权威——不进裁决链（memory 冲突以 memory 为准）、SSOT 修正与归并不回改（历史不改写）、恢复不读（AI 只写不读）。落盘同轮二选一显式留痕：约束后续工作 → 经 `::remember` 写入 memory；不约束 → 尾标 `（不约束后续工作）`——严禁不表态（::audit 第 9 项对账兜底）。
- **`::next [方向]`（断点规划）**：① 断点明确且未过期 → 报告内容，确认是否开工；② 断点为空/`等待拆解`/已过期 → 读 memory 正文 + `tail -n 20` devlog，推导候选子任务（**≤3 个，各一行理由**），用户选定或默认第一项 → 按 §3 口径写入断点并校验 → 开工。**严禁复述 memory 全文、严禁超出 3 候选**——规划结果必须落盘为断点，否则本轮规划等于白聊。
- **`::board`（任务看板，多任务并行选择入口）**：跑 `toolbox run panel --board` 取逐任务表（`<epic> ｜ 最后活动 <日期> ｜ 断点：<内容>`，当前绑定标 ▶，misc 标「常驻」，memory 头部 `state: maintenance` 标「(维护)」，按最后活动降序），按下方「面板判读协议」渲染，**末尾固定附一行跨 AI 恢复咒语**：`其他 AI/工具：读 context/epics/<任务名>/memory.md 按断点继续`。只读不写；用户选定后走 `::bind` 正常绑定流程。
- **`::status`（运行态快照）**：一条调用链返回——CURRENT 内容、断点行、devlog（绑定 epic 与 misc 两处）与 lessons 待归并计数（`tail -n 20 | grep -c '^- \['`）、`wc -l` memory 行数。**只读不写，输出 ≤5 行**。
- **`::help`（面板入口，求助第一句）**：跑 `toolbox run panel` 取事实块（绑定/断点/任务活动/计数），按下方「面板判读协议」渲染四区——**我在哪 / 现状 / 建议动作 / 按意图命令速查**（速查一行分组即可，全量命令清单含含义仅用户显式索要时经 `toolbox run cmds` 收集输出，cmds 缺失降级读 COMMANDS.md）；新会话 / 跨 IDE 求助入口；排错协作时附一行「人类侧排错说明：`problem-triage/manual.md`」。
- **面板判读协议（::help / ::board 共用，写死）**：① **事实以脚本为唯一来源**——跑 `toolbox run panel` 后严禁再 grep/读文件重复取证；脚本缺失（未入池环境）才降级手推（board 用 ls+grep 现场推导口径）；panel 自身故障（exit 2）时可改跑轻量 `toolbox run ctx-status`（仅 ::status 数据面）；② 事实块**原样嵌入**，数字/日期严禁改写或凭印象修正，数据可疑重跑脚本，不手改；③ **建议动作由 AI 结合本窗口语境自产**（≤3 条，有信号才写、无信号不凑数）——机建议位暂留空，稳定复现的建议按 §8 收敛复盘口径逐步固化进脚本；④ 追问按需 `toolbox run panel --deep <epic>` 单点取数（债面追问用 `panel --debt`：标记分布 top 文件 + 白名单 + 上次体检时效），不做全量深挖；⑤ 常态回复 ≤10 行；面板只读只建议，执行仍走 §9 触发纪律；⑥ **字段同步**：panel 输出字段增删的当轮，同步依赖它的卡模板（§3 绑定卡）——panel 改字段与卡模板改字段是同一轮义务。

## 7. 审计与质检 (Audit)

**触发**：① `::audit` 手动；② `::done` 第一步**强制执行**；③ 建议时机：多机同步/分支切换后、久别重置恢复后。**机械项可选预填**：先跑 `toolbox run ctx-audit --root <项目根>`（委托 context-lint 代跑机械项，人判项标 ❓ 交 AI 补判），按其结果逐项输出 ✓/⚠——清单语义以本节为唯一事实源，脚本仅是执行器；脚本缺失时照常手工逐项。

**清单（12 项）**（逐项一行输出 `✓ / ⚠ + 动作建议`）：

1. **断点新鲜度**：`grep -n '^- \[断点\]' memory.md` 对照 devlog 尾部——已被完成工作超越即 ⚠，转 `::next` 重写；
2. **新旧并存**：通读 memory 正文，同主题残留多条矛盾结论即 ⚠，按 `[SSOT 修正]` 优先级当场收敛；
3. **devlog 积压高价值项**：devlog 存在未归并的 `[SSOT 修正]` 即 ⚠，**立即执行 §4 归并**（堵重置复活缺口）；
4. **记忆补记审查**：对照本窗口结论与 memory 正文——「聊定了但没落盘」的决策即 ⚠，经确认按 `::remember` 口径补写（记忆库自查生长，对应插件的回合内记忆审查，此处为手动低频触发）；
5. **lessons 与规范去重**：对照现有规范 skill 清单，已被覆盖的正文条目降级为一行 `Ref:`；
6. **尺寸健康**：`wc -l` 三文件，memory 正文 >150 行 ⚠ 建议收尾或拆分（§4 软上限）；
7. **孤儿 epic**：`ls context/epics/` 对照 CURRENT 与各 devlog 修改时间，长期未动者提示 `::done` 或确认搁置（**misc 为常驻挂靠、维护态（state: maintenance）epic 已收尾，均不算孤儿**）；
8. **头部校验**：`head -n 7` 各记忆文件，字段缺失/角色与目录不符即 ⚠；
9. **指针抽查**：grep 各薄指针（COMMANDS.md 命令手册、dev-guide §3 命令速查、项目索引关联行）与各 memory.md 挂载行（路径存在、非 deprecated 墓碑；机械项由 audit 钩 context-lint 挂载面代跑）的锚点串是否在目标文件真实存在——不存在即 ⚠，当场修指针；**挂载行指向域内 `todos.md` 的过渡态 epic 每轮附一行提示「是否已有真实设计内容可升级挂载」，确认具备则改指正式文档**；改过其他 skill 节号/节名后必查（引用方含 COMMANDS.md），例行审计抽查 2~3 条控成本。另含 **decisions↔memory 契约对账**：decisions.md 各节最新 1~2 条在对应 epic 的 memory 正文有无约束型契约行——缺失即 ⚠，经确认补 `::remember`（::adr 单向联动无写入校验，此处兜底）。project-local skill 对代码现实的锚点存在性（路径/命令/类名 FQN）可跑 `toolbox run skill-verify` 代跑（机械半边，语义核实留 AI）。
10. **skill 卫生抽查（事实指针化）**：规范类 skill 正文严禁自带易漂移事实（模块结构/领域清单/编译命令/依赖版本号/环境限制），一律指针到项目事实源（workflow 类 skill、项目索引），grep 抽查疑似事实锚点，正文自带非指针出处即 ⚠ 当场改写；description 是路由触发信号非正文，只留项目锚点+技术栈+高频症状关键词，细节沉正文；description 机械上限 550 字符（ctx-audit 项 J 检查，超限即 ⚠ 压缩——加载器拒载边界的实测值，该检查属加载器行为微操，加载器升级后与本句一同退役）。新增 skill 或改过事实性段落后必查，例行抽查 2~3 条控成本。
11. **toolbox 巡检（agent-toolbox）**：toolbox 已初始化（`~/.agents/toolbox/` 存在）时执行 `toolbox run-hooks audit --quiet`——**以退出码判定**：exit 0 = ✓，exit 1 = ⚠（`--quiet` 静默一切输出，只看退出码；需 FAIL/ERROR 明细时再跑不带 `--quiet` 的 `toolbox run-hooks audit`，或 `toolbox run cl` 裸跑），按 memo-collector 口径转 `风险` 待办；空池/未初始化直接 ✓ 跳过；另跑 uscan/dscan/ascan 三扫描各一次 `--json`，`stale_whitelist` > 0 即 ⚠（失效白名单行＝卫生级——工具不因其改退出码，裁决收口在本项；处置：对照 `--md` 明细核对后清理确认失效行，恢复监控）。
12. **验证缺口抽查**：grep devlog 尾部最近 2~3 条 `[变更]` 行是否各有同日 `[验证]` 账本行——[变更] 无 [验证]、或 [验证] 写「未执行」无理由即 ⚠，补验证或确认补因；人工抽查（机械化待办，口径同第 9/10 项）。

**修复纪律**：琐碎修复（归并积压、补记、降级 Ref、重写断点）列清单经确认当场执行；结构性修复（拆分、归档）转 `::done` 或用户决策。**审计轮不追加任何日志**（豁免规则适用）。

**`::verify <epic|lessons|all>`（账实对账）**：上方十二项是**账账相符**（记忆与 skill 文档内部一致）；verify 验**账实相符**（记忆 vs 代码现实）——裁决链已把 memory 抬到最高权威，无验真机制即裸奔。
- **范围钳制**：仅验可机械定位的断言（引用具体类名/路径/属性/阈值/开关的结论）；抽象理由/偏好一律标 ❓ 交人工，不猜测。
- **三态输出**（≤15 行）：`✅ 仍成立` / `❌ 已失效（附代码证据行）` / `❓ 无法机械验证`。
- **修复路径**：❌ 项提议**批量 `[SSOT 修正]`**（memory / lessons 各走 §2 对应通道），经用户确认落盘；lessons 失效规则优先修——过期教训会误导未来每一轮排错。
- **建议时机**：里程碑收尾、久别重开、`lessons.md` 归并出新规则后（趁热验真）、起疑时。仅用户显式触发。

## 8. epic 收尾 (Closure)

- **`::done`**（**misc 常驻，不适用收尾**）：第一步**强制执行 §7 审计，存在 ⚠ 项即中止收尾、先修复**；通过后先执行**决策过程归档**（同 §4：devlog 决策/权衡条目写进挂载底子文档 `## 决策日志` 专节，完成后才可清空 devlog）；随后执行**收敛复盘**（升舱后输出一行度量，见下）；随后**标记强制结算**——本 epic 引入的 `// UNCERTAIN:` / `// DEGRADE:` 标记逐条清零，三选一经确认：补测试实证后删标（删标判据 = ai-sideeffect-guard §6）/ 升级正式 ADR（::adr 落 decisions.md）/ 转 todos `(风险)` 待办并注明 epic 归档；带日期指纹的标记按日期核龄，批量定性须逐条留痕防收尾洗白——**逾期未处置标记是唯一阻断项**（标记本身是信标非罪证，阻断边界见 SKILL.md §2）；结算后必出**收尾汇总卡**（标记/白名单/Hypothesis 实数，全零也出卡，数字以四工具扫描与台账实数为准）；随后**待办先处置清零**（memo-collector §4：完成流转/转全局/删除，经确认；`epics/<名>/todos.md` 随 epic 目录留存——目录不搬，重开后继续可用）；再将 memory.md 提炼为 **≤10 行结论块**（保留头部；断点改写交由 close 机械件，此处不动断点），`decisions.md` 该 epic 节保留（epic 仍在维护态，仅真退役时人工移入 archive）；随后**收尾清账**——`toolbox run devlog clear <名>`（清空 devlog 追加区 + 头部 total-merged+1/last-merge 同步；**前置 = dlog 决策归档与本轮 memory 提炼均已完成**，追加区内容的三处落点 = 挂载文档「## 决策日志」/misc-decisions.md/memory 结论块）；随后**维护态收尾**——`toolbox run devlog close <名> <完结说明>`（memory 头部写 `state: maintenance` + 断点改「已完结：<说明>」+ `CURRENT` 改写为 `epic: none`），一行回复确认。**epic 目录不搬**，留在 `context/epics/<名>/` 进入维护态；`context/archive/` 仅收真退役功能（人工确认后移入）。重开 = `toolbox run devlog reopen <名>`（清标记+断点回「等待拆解」+CURRENT 指回）后 `::bind` 续绑——devlog 已清账，历史条目不会混入后续自动归并；**严禁另起新 epic 绕开维护态**。

**收敛复盘（::done 内置，升舱 L2→L3）**：收尾时逐项核对——① lessons 正文中已被验证多次、表述稳定的条目 → 提议固化进规范/事实源 skill（原条目降级一行 `Ref:`，对齐 §7 第 5 项口径）；② devlog/待办中同类澄清 ≥2 次的约束 → 按 memo-collector「咒语」行固化信号提议升级事实源；③ todos 中 `[long]` 条目按 memo-collector §4 重评；④ ::verify 近期 ❌ 项确认已批量 SSOT 修正。全部走「提议 → 用户确认 → 落位」，AI 不静默改写 skill。收尾回复附一行**收敛度量**：`收敛: +N 固化 / M 待定 → 事实源`（N=本轮升舱条数，M=仍留 L2 的条数）——跨 epic 观察趋势，固化递增、待定递减即体系在收敛。
