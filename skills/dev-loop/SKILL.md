# Skill: Dev-Loop (无状态极简交互 SOP - V3.5)

> **管辖边界声明**：本 Skill 仅约束回复格式、Token 管控、日志协议与全局护栏（防死锁/防虚构/破坏性确认/静态强约束/契约保护，见下方「全局护栏协议」），**全项目通用**。代码规范与环境限制优先遵循**当前项目挂载的项目级 Skill 或 AGENTS.md**（如 stock-calculator 项目对应 `stock-calculator-backend-dev` / `stock-calculator-workflow`）；无挂载时以项目自身约定为准。

**冲突裁决链**：绑定 `memory.md` 的显式最新决策 ＞ 项目级 Skill / AGENTS.md ＞ 本 Skill 规约——memory 决策属有意覆盖；推翻项目规范时，以 `[SSOT 修正]` 审计行留痕为准。

**全局护栏协议（全时段生效）**：

0. **总纲——求助人类优先（Human-in-the-loop）**：任何无法自行安全推进的时刻（资源缺位 / 同一卡点重复失败 / 高风险动作 / 不可排他的歧义），打断并请求用户协助永远优先于自主猜测与硬试；下列各项皆为本条的具体化。

1. **输入校准与零干预**：
   - **静默容错**：面对错别字/同音字/笔误，在不改变原意的前提下静默修正并继续执行，严禁回应无意义的纠错提示。
   - **歧义阻断**：若错别字或模糊表述引发破坏性或不可排他的重大歧义，立刻停下，仅用一句话向用户确认，严禁盲目猜测并触发工具。
   - **零干预原则**：仅校正输入，不干预思考。严禁对用户的未受邀方案进行主动质疑或未经请求的发散补充（触发歧义阻断或本协议第 4 条高危二次确认时除外）。
2. **资源缺位主动拦截（资源类）**：
   - **不凭空假设**：当执行任务缺少必要资源（如日志截屏、具体配置文件、环境 API、未暴露的结构体定义、权限密钥等）时，**必须立刻打断并向用户索取**。
   - **禁止虚构**：严禁自行伪造假日志、假配置或假接口返回值继续往下推导。
3. **两次尝试熔断机制（难题/死锁类）**：
   - **硬性熔断**：针对同一个报错、测试失败或逻辑卡点，**连续尝试修正 2 次仍未解决时，必须立即停止修改**；用户补充新信息或明确指示继续后，计数重置。
   - **问题暴露格式**：第 3 轮禁止继续改代码，必须向用户输出以下卡点描述：
     1. `[已尝试方案]`：过去 2 次具体的修改与失败结果。
     2. `[核心卡点]`：当前无法突破的具体报错或矛盾点（附关键报错片段）。
     3. `[建议方向]`：提供 1~2 个需要用户决策或补充信息的可能排查方向。
4. **隐性环境与破坏性隔离（环境类）**：
   - **假设显式化**：在涉及环境命令、依赖版本、操作系统特性的操作前，若未确定环境，先向用户确认或通过最轻量的命令探针确认，禁止假设环境。
   - **高危操作二次确认**：破坏性动作（如删除数据表、清空队列、强制覆盖分支）前，必须列出影响范围并等待用户显式授权。
5. **静态强约束（生成类）**：所有生成代码必须经本地工具链（compile / type-check / lint）校验后方可交付（无法校验时如实说明，严禁以「看着合理」替代），严禁引入不存在的 API 或类库；未经用户显式确认禁止引入新第三方依赖，优先复用项目已有工具类。
6. **契约保护（改动类）**：严禁隐式破坏现有公共接口与底层数据模型契约；大面积跨文件改动先列影响清单经确认再动手，有疑虑立刻停下确认。

## 0. 目录结构 (Layout)

```
context/                      ← 可见目录，作为项目的一部分提交 git
├── CURRENT                   ← 当前绑定的大功能（个人指针，加入 .gitignore；日常默认 epic: misc，epic: none 仅明确停工时用，禁止空文件）
├── epics/                    ← 长期记忆 + 过程日志，按大功能（epic）组织
│   ├── misc/                 ← 常驻杂项 epic：散修/小改动统一挂靠，长成大功能则 /bind 转正
│   └── <大功能名>/
│       ├── memory.md         ← 长期记忆 SSOT（决策/架构/进度 + 断点；会话恢复只读此文件）
│       └── devlog.md        ← 开发过程日志（追加区，≥5 条自动归并进 memory.md）
├── archive/                  ← 已完结 epic（memory 已提炼 ≤10 行，按需人工翻档）
├── lessons.md                ← 项目经验总结（全局单文件，项目的一部分）
└── decisions.md              ← 决策洞察档案（/adr 写入；按 epic 分节 + misc 兜底；AI 只写不读，不进裁决链，历史不改写）
```

**文件头部声明 (File Header)**：所有记忆文件以固定 YAML 头部开头：

```yaml
---
dev-loop: memory | devlog | lessons | decisions
format: v1
epic: <大功能名 | global>      # lessons/decisions 为全局单文件，固定写 global
total-merged: <累计归并次数>
last-merge: <YYYY-MM-DD | none>
---
```

**头部维护规则（写死）**：
- 头部仅在**文件创建**与 **/merge 归并**时写入/更新（`total-merged` +1、`last-merge` 刷新）；追加轮**严禁触碰头部**；
- 头部**不含 pending 计数**——条目数始终由现实推导（§2 `tail | grep -c`），不缓存、零漂移；
- 会话恢复时先 `head -n 7` 校验文件角色与 epic 同 `context/CURRENT` 一致，再继续。

## 1. 动态输出策略 (Output Strategy)

修改代码时，按以下优先级执行，严禁主动打印未经修改的全量文件：

1. **Tool Edit 原地修改**：在 Write Profile 模式下，直接调用写/改文件工具更新目标代码（Token 消耗最低且零手动差错）。
2. **局部代码块 (Code Snippet)**：仅输出包含上下文改动的核心函数/类块，并标明文件路径与插入位置。
3. **降级 Unified Diff**：仅在用户显式要求或存在自动化 Apply Diff 工具时使用。

## 2. 日常交互与日志协议 (Protocol)

当本轮发生**任一触发**——产生业务代码/配置变更（Diff）、**解决了具备通用价值的 Bug**、显式推翻既有决策——Agent **必须用 Tool 追加对应日志**（对应下方第 1 / 2 / 3 条），严禁仅在聊天框文本回复：

1. **追加开发日志（devlog）**：调用写/改文件工具，将以下单行内容追加至 `context/epics/<大功能名>/devlog.md` 底部：
   `- [YYYY-MM-DD] [变更]: <1句话精炼说明完成的子任务/配置变更>`

2. **追加 Lesson 日志（仅限具备通用价值的 Bug，一旦满足即必记）**：若排查并解决了此类 Bug，调用工具追加至 `context/lessons.md` **底部追加区**：
   `- [<模块>] <报错现象> ➔ <根本原因> ➔ <避坑规则> (Ref: <大功能名>)`
   *（`lessons.md` 为双区结构：正文＝项目经验总结 SSOT（按模块归类的避坑规则），底部＝教训流水；排错轮次开始时应先读正文对照历史规则，再动手排查。**正文行禁用 `- [` 开头**——该前缀专属追加区，保证 grep 计数不被正文污染。）*

3. **SSOT 修正（决策推翻时强制，不依赖 Diff，双重动作）**：当用户显式推翻或废弃既有决策/结论时（即使本轮无任何代码变更）：
   ① **即时生效**：当轮用 Edit/sed 将 `memory.md` 正文中对应旧结论改写为新结论——**修正不等待归并**，消除「重置窗口缺口」，memory 恒为最新共识；
   ② **审计留痕**：向 `context/epics/<大功能名>/devlog.md` 底部追加 `- [YYYY-MM-DD] [SSOT 修正]: 旧结论 <X> 已废弃 ➔ 新结论 <Y>`（计入归并阈值）。

*(豁免规则：以下轮次**禁止追加任何日志**——① **未产出可留存结论的**纯咨询/排错轮次；② 执行 `/merge`、`/bind` 等协议操作的轮次；③ 除 Lesson / SSOT 修正落盘外，仅维护 `context/` 文档本身的轮次（含日志追加自身产生的写入，防递归记日志）。)*

**不受豁免（即使无代码 Diff 也必须落盘）**：解决了具备通用价值 Bug 的排错轮次 → 记 Lesson；推翻既有决策的轮次 → 记 SSOT 修正。

**实现口径（写死，防会话间漂移）**：
- **追加**：一律用终端 `cat >> <目标文件> <<'EOF'` + 单行日志 + `EOF`，一次调用完成；**严禁先整读再重写**（成本随文件增长线性变贵）。终端不可用时降级：Read 仅取尾部若干行 → Edit 锚定原末行追加。日志行内避免 `${...}` 字面量（终端静态扫描会拒），必要时只写属性名。
- **计数（低频校验，非每轮）**：本窗口上下文即短期计数——Agent 可见本窗口内已追加的日志轮数，**不必每轮实数计数**；仅在 ① 恢复后首轮 ② 上下文计数已近/达阈值 ③ 长窗口或不确定时，用 `tail -n 20 <目标文件> | grep -c '^- \['` 做一次实数校验。严禁整文件 Read 数条目。

## 3. 状态自恢复与绑定协议 (Bootstrap & Binding)

- **状态恢复**：新会话开场（或 Cmd+R / Ctrl+R 重置后），Agent 优先调用工具读取项目根目录 `context/CURRENT`（内容格式：`epic: <大功能名>`），随后**只读 `context/epics/<大功能名>/memory.md`（蒸馏后的长期记忆与断点）**即可恢复共识——不读 devlog、不依赖对话历史（可先 `head -n 7` 校验头部角色/epic 与 CURRENT 一致）。**若 CURRENT 为 `epic: none` 或文件缺失**（新机器 clone 后的常态——CURRENT 被 gitignore）：视同无活跃 epic，仅提示用户 `/file` 绑定，严禁自行挑选开工；**CURRENT 指向的 epic 目录不存在或头部校验失配**：以 `ls context/epics/` 实际目录为准列出候选、提示重新 `/file` 绑定，严禁自行猜绑。
- **开场环境检查（agent-toolbox，fail-open）**：若 shim `~/.local/bin/toolbox` 或 `~/.agents/toolbox/` 存在，开场读 CURRENT 前先执行 `toolbox run-hooks bootstrap --quiet`：exit 0 静默继续；非 0（工具 FAIL/自身故障）**严禁阻塞恢复流程**，仅在开场回复末尾附一行 ⚠ 提示（FAIL 明细按 memo-collector 口径转 `风险` 待办）。未初始化 toolbox 的环境直接跳过本项。
- **断点指针 (Checkpoint)**：`memory.md` 正文末尾固定维护 `## 断点` 章节，内容恒为一行：`- [断点] 下一步：<具体子任务>`（无待办时写 `等待新子任务`，**严禁留空或过期**）。它是唯一**不可由文件推导**的状态（下一步意图），故必须显式维护。维护规则：任何使「下一步」改变的轮次（Diff / SSOT 修正 / 结论性咨询）收尾时刷新；实现固定用 `sed -i 's|^- \[断点\].*|- [断点] 下一步：<新内容>|' <memory.md> && grep -c '^- \[断点\]' <memory.md>`——sed 匹配零行时会**静默成功**，必须以 grep 结果校验，**非 1 即异常**：0 ＝ 章节缺失→重建 `## 断点`＋断点行；>1 ＝ 重复→去重保留最新（内容含特殊字符时改用 Edit 锚定该行）。恢复收益：读 CURRENT（槽位）+ 读 memory（结论＋断点）→ 直接开工，恢复从「推断」变「查表」，开场白可简化为「继续」。
- **绑定与切换**：当用户发送 `/file <大功能名>` 或 `/bind <大功能名>` 时，Agent 必须调用工具将 `context/CURRENT` 改写为 `epic: <大功能名>`（忽略路径与后缀，只取大功能名）；**若为切换且旧 epic 的 devlog 存在未归并条目，先按 §4 归并旧 epic 再改写 CURRENT**（不留跨会话积压）；若 `context/epics/<大功能名>/` 不存在，**同时创建该目录及带 §0 文件头部的 `memory.md`（含 `## 断点` 初始行 `- [断点] 下一步：等待拆解`）与 `devlog.md`**。完成后极简确认绑定成功，并按任务形态附一行提示：大需求/复杂迭代建议加载 dev-guide 按流程骨架推进；散修挂 misc 即可，不推流程。**裸调用（`/file` 无参数）**：只读列出 `ls context/epics/` 候选与当前绑定，提示选择，不写任何文件。
- **杂项挂靠 (misc)**：散修/小改动（不够格建正式 epic）统一挂靠常驻的 `context/epics/misc/`——日志直接落 `misc/devlog.md`，**不要求为此切换 CURRENT**（挂靠点由任务性质决定，CURRENT 只记主战场）；CURRENT 日常默认 `epic: misc`（散修轮次同样走 §2 日志协议，lessons 记 `Ref: misc`）；misc 内散修若长成大功能（连续多轮），`/bind <新名>` 转正，misc memory 归并时只留一行「已转正为 <新名>」索引，日志不搬家；misc 断点恒为「等待散修任务」。
- **自动重构 (Auto-Refactor)**：本轮日志追加完成后，Agent 以**上下文短期计数**判断是否近阈值（恢复后首轮、长窗口或不确定时，按 §2 实现口径实数校验一次），**本轮追加目标的 `devlog.md`（含 misc 挂靠）**与 `lessons.md` **任一 ≥ 5 条**即在本轮末尾**针对该目标 epic 自动执行 §4 双文件压缩**（无需用户触发），并在回答末尾附注一行：
  > ⚙️ **[自动重构完成]**：追加日志已归零压缩（阈值触发）。建议方便时 Cmd+R / Ctrl+R 重置窗口。

## 4. 重构与归纳 (Compression Procedure)

**触发方式有二**：① **自动**——§3 阈值达成时本轮末尾自动执行；② **手动**——用户随时发送 `/merge`。两者执行同一套**双文件压缩**流程：

1. **大功能长期记忆（memory.md）**：将 `context/epics/<大功能名>/devlog.md` 底部的碎片化日志提炼归纳进 `memory.md` 正文（SSOT），并清空 devlog 追加区；**两文件头部同步更新**（`total-merged` +1、`last-merge` 刷新，按 §0 规则）；重写时 `## 断点` 章节原样保留最新值。**`[SSOT 修正]` 条目拥有最高归纳优先级：必须以其覆盖正文中对应的旧结论，严禁新旧并存**（修正已按 §2 当轮即时生效，此处仅为兜底）。
2. **项目经验总结（context/lessons.md，全局单文件）**：将其底部追加区的教训流水去重、合并同模式、按模块归纳进正文（项目级避坑规则 SSOT），并清空底部追加区；头部同步更新（`total-merged` +1、`last-merge` 刷新）；`[SSOT 修正]` 优先级规则同样适用。
3. **极简回复**：完成后，仅回复（自动触发时为附注）一行：
  > *"已完成 `<大功能名>` 记忆归并（devlog → memory.md）与 `lessons.md` 重构，追加日志已归零压缩。请按 Cmd+R / Ctrl+R 重置窗口。"*

*（`context/` 整体作为项目的一部分提交 git（仅 `CURRENT` 为个人指针，加入 `.gitignore`）：自动压缩均可回溯，归纳失真时细节可从历史找回。**git 冲突面**：append-only 的 devlog 走合并无痛；`memory.md` / `lessons.md` 为编辑型文件，多机或多端同时归并必然冲突且发生在提炼后的正文上——单人多机需「切换机器前 commit」纪律，团队协作时此为已知取舍。**软上限**：`memory.md` 正文超过 ~150 行时，应考虑该 epic 收尾归档或拆分为新 epic，恢复成本随正文缓慢上升。）*

---

4. **归并事故回滚（灾难恢复纪律）**：归并或记忆写入导致 memory.md / lessons.md 质量断崖式下跌（关键决策被总结错、断点丢失、正文失真）时，**严禁 Agent「尝试自己重写修复」**——立即 `git checkout -- context/<epic>/memory.md` 恢复最近提交版本（lessons.md 同理），随后向用户报告事故经过，由人工微调补记；存疑时先 `git --no-pager log -p -- context/` 对照历史。前提：`context/` 全目录（除 CURRENT）保持纳入 git；devlog 为 append-only，一般无需回滚。

## 5. 实测闭环验证 (1 分钟)

1. **绑定验证**：发送 `/file <大功能名>`（示例：`/file e2ee-auth`）→ Agent 用 Tool 将 `epic: <大功能名>` 写入**该项目**的 `context/CURRENT`，并自动创建 `context/epics/<大功能名>/` 骨架。
2. **物理重置验证**：按 Cmd+R (Mac) / Ctrl+R (Win) 清空窗口历史。
3. **无状态恢复验证**：发送 *"读 `context/CURRENT`，开始下一个子任务：[xxx]"* → Agent 无追问直接恢复绑定并开工。

**成功标准**：
- Agent 不反问绑定了哪个大功能，而是直接以 `memory.md` 的长期记忆继续工作；
- 代码变更后日志由 Tool 自动落盘至 `context/epics/<大功能名>/devlog.md`，而非打印在聊天框内。

## 6. 附属指令流程 (Manual Ops)

- **`/remember <事实>`（人工记忆入口）**：将结论**直接写入 memory.md 正文**（`- [YYYY-MM-DD] <事实>`，或归入相应小节）。用户主动发起即视为已确认，无需 Diff/推翻触发；若影响下一步，同轮按 §3 口径刷新断点。**不写 devlog**——已直入 SSOT，无归并需求。
- **`/adr <标题>`（决策洞察档案入口）**：将本窗口刚敲定的方案权衡（AI 的优缺点对比/架构评估属高价值资产，用户一句「/adr 记下这个权衡」即触发）以多行条目落 `context/decisions.md`——**按 epic 分节 + `## misc` 常驻兜底**（与 todos.md 同构：节不存在时 Edit 锚定 `## misc` 行上方插入新节，`## misc` 恒为最后一节；散修/跨域/通用决策一律 misc），节内最新在上。条目格式（写死）：`### [YYYY-MM-DD] <标题> (src: ai | 用户)` 起头的多行块，固定四段——**场景/痛点、可选方案（含否决理由）、最终决定、AI 洞察**。**定位护栏（写死）**：decisions.md 是历史档案非权威——① 严禁进裁决链，与 memory 冲突时以 memory 为准；② SSOT 修正与归并**不回改** decisions（历史不改写，防篡改档案）；③ 恢复流程不读（AI 只写不读，膨胀零 AI 成本）。若该决策约束后续工作，同轮附一行契约经 `/remember` 写入 memory（单向联动，`/remember` 不反向触发 `/adr`）。
- **`/next [方向]`（断点规划）**：① 断点明确且未过期 → 报告内容，确认是否开工；② 断点为空/`等待拆解`/已过期 → 读 memory 正文 + `tail -n 20` devlog，推导候选子任务（**≤3 个，各一行理由**），用户选定或默认第一项 → 按 §3 口径写入断点并校验 → 开工。**严禁复述 memory 全文、严禁超出 3 候选**——规划结果必须落盘为断点，否则本轮规划等于白聊。
- **`/status`（运行态快照）**：一条调用链返回——CURRENT 内容、断点行、devlog（绑定 epic 与 misc 两处）与 lessons 待归并计数（`tail -n 20 | grep -c '^- \['`）、`wc -l` memory 行数。**只读不写，输出 ≤5 行**。

## 7. 审计与质检 (Audit)

**触发**：① `/audit` 手动；② `/done` 第一步**强制执行**；③ 建议时机：多机同步/分支切换后、久别重置恢复后。

**清单（11 项）**（逐项一行输出 `✓ / ⚠ + 动作建议`）：

1. **断点新鲜度**：`grep -n '^- \[断点\]' memory.md` 对照 devlog 尾部——已被完成工作超越即 ⚠，转 `/next` 重写；
2. **新旧并存**：通读 memory 正文，同主题残留多条矛盾结论即 ⚠，按 `[SSOT 修正]` 优先级当场收敛；
3. **devlog 积压高价值项**：devlog 存在未归并的 `[SSOT 修正]` 即 ⚠，**立即执行 §4 归并**（堵重置复活缺口）；
4. **记忆补记审查**：对照本窗口结论与 memory 正文——「聊定了但没落盘」的决策即 ⚠，经确认按 `/remember` 口径补写（记忆库自查生长，对应插件的回合内记忆审查，此处为手动低频触发）；
5. **lessons 与规范去重**：对照现有规范 skill 清单，已被覆盖的正文条目降级为一行 `Ref:`；
6. **尺寸健康**：`wc -l` 三文件，memory 正文 >150 行 ⚠ 建议收尾或拆分（§4 软上限）；
7. **孤儿 epic**：`ls context/epics/` 对照 CURRENT 与各 devlog 修改时间，长期未动者提示 `/done` 或确认搁置（**misc 为常驻挂靠，不算孤儿**）；
8. **头部校验**：`head -n 7` 各记忆文件，字段缺失/角色与目录不符即 ⚠；
9. **指针抽查**：grep 各薄指针（dev-guide §3 命令速查、项目索引关联行）的锚点串是否在目标文件真实存在——不存在即 ⚠，当场修指针；改过其他 skill 节号/节名后必查，例行审计抽查 2~3 条控成本。
10. **skill 卫生抽查（事实指针化 + description 预算）**：① 事实指针化——规范类 skill 正文严禁自带易漂移事实（模块结构/领域清单/编译命令/依赖版本号/环境限制），一律指针到项目事实源（workflow 类 skill、项目索引），grep 抽查疑似事实锚点，正文自带非指针出处即 ⚠ 当场改写；② description 预算——description 是路由触发信号非正文：新建目标 ≤~250 字符、硬顶 550（awk FNR==3 length 口径；实测边界 547 可载、995 被系统拒载），超限即把完备症状清单/细节沉入正文 §一，description 只留项目锚点 + 技术栈 + 高频症状关键词；新增 skill 或改过事实性段落/description 后必查，例行抽查 2~3 条控成本。
11. **toolbox 巡检（agent-toolbox）**：toolbox 已初始化（`~/.agents/toolbox/` 存在）时执行 `toolbox run-hooks audit --quiet`——非空输出即 ⚠ 项（FAIL/工具故障），按 memo-collector 口径转 `风险` 待办；空池/未初始化直接 ✓ 跳过；

**修复纪律**：琐碎修复（归并积压、补记、降级 Ref、重写断点）列清单经确认当场执行；结构性修复（拆分、归档）转 `/done` 或用户决策。**审计轮不追加任何日志**（豁免规则适用）。

**`/verify <epic|lessons|all>`（账实对账）**：上方十项是**账账相符**（记忆与 skill 文档内部一致）；verify 验**账实相符**（记忆 vs 代码现实）——裁决链已把 memory 抬到最高权威，无验真机制即裸奔。
- **范围钳制**：仅验可机械定位的断言（引用具体类名/路径/属性/阈值/开关的结论）；抽象理由/偏好一律标 ❓ 交人工，不猜测。
- **三态输出**（≤15 行）：`✅ 仍成立` / `❌ 已失效（附代码证据行）` / `❓ 无法机械验证`。
- **修复路径**：❌ 项提议**批量 `[SSOT 修正]`**（memory / lessons 各走 §2 对应通道），经用户确认落盘；lessons 失效规则优先修——过期教训会误导未来每一轮排错。
- **建议时机**：里程碑收尾、久别重开、`lessons.md` 归并出新规则后（趁热验真）、起疑时。仅用户显式触发。

## 8. epic 收尾 (Closure)

- **`/done`**（**misc 常驻，不适用收尾**）：第一步**强制执行 §7 审计，存在 ⚠ 项即中止收尾、先修复**；通过后将 memory.md 提炼为 **≤10 行结论块**（保留头部与 `## 断点` 改写为完结说明），目录移入 `context/archive/<名>/`，`decisions.md` 中该 epic 节若有条目则整体移入 `context/archive/<名>/decisions.md` 并删除该节，`CURRENT` 改写为 `epic: none`，一行回复确认。收尾后该 epic 退出活跃集，恢复流程永不再读它（按需人工翻档）。

## 9. 指令总表 (Command Surface)

**指令体一律薄指针（「执行 §X」），流程正文全 skill 只此一份**——哪条指令开始自带全文，哪条就是漂移的开始。

| 指令 | 职责 | 指向 |
|---|---|---|
| `/file` `/bind` | 绑定/切换（切走先归并旧 epic） | §3 |
| `/remember` `/next` `/status` | 记忆入口 / 断点规划 / 快照 | §6 |
| `/adr` | 决策洞察档案（权衡详存，AI 只写不读） | §6 |
| `/merge` | 手动归并（§3 自动触发的覆盖口） | §4 |
| `/audit` `/verify` | 十一项质检（账账）/ 记忆对现实（账实） | §7 |
| `/done` | epic 收尾（内含审计） | §8 |
| `/help` | 输出本表与当前绑定状态（新会话 / 跨 IDE 求助入口） | §9 |

**分工**：干活归自动化（日志追加、≥5 归并协议自走）；指令只管自动化覆盖不了的三类时刻——**人工判断**（/remember、/adr、/done）、**规划决策**（/next）、**系统健康**（/status、/audit、/verify）。

**跨 skill 速查**：构建/验证/lint 等项目专属命令见当前项目 project-local 索引「命令速查」节（机制见 project-index）——本表只覆盖本 skill 的指令面。

**触发纪律**：全部指令仅用户显式触发；Agent 严禁自主执行 `/audit` / `/verify` / `/done`；一切修复经确认后落盘。
