# Skill: Dev-Loop (无状态极简交互 SOP - V3.6)

> **管辖边界声明**：本 Skill 仅约束回复格式、Token 管控、日志协议与全局护栏（防死锁/防虚构/破坏性确认/静态强约束/契约保护，见下方「全局护栏协议」），**全项目通用**。代码规范与环境限制优先遵循**当前项目挂载的项目级 Skill 或 AGENTS.md**（项目专属规范 skill 挂 project-local `<repo>/.agents/skills/`，如后端仓的 `stock-calculator-backend-dev` / `stock-calculator-workflow`；未自动发现时直接读该路径）；无挂载时以项目自身约定为准。

**冲突裁决链**：绑定 `memory.md` 的显式最新决策 ＞ 项目级 Skill / AGENTS.md ＞ 本 Skill 规约——memory 决策属有意覆盖；推翻项目规范时，以 `[SSOT 修正]` 审计行留痕为准。

**全局护栏协议（全时段生效）**：

0. **总纲——求助人类优先（Human-in-the-loop）**：任何无法自行安全推进的时刻（资源缺位 / 同一卡点重复失败 / 高风险动作 / 不可排他的歧义），打断并请求用户协助永远优先于自主猜测与硬试；下列各项皆为本条的具体化。

1. **输入校准与零干预**：
   - **静默容错**：面对错别字/同音字/笔误，在不改变原意的前提下静默修正并继续执行，严禁回应无意义的纠错提示。
   - **歧义阻断**：若错别字或模糊表述引发破坏性或不可排他的重大歧义，立刻停下，仅用一句话向用户确认，严禁盲目猜测并触发工具。
   - **零干预原则**：仅校正输入，不干预思考。严禁对用户的未受邀方案进行主动质疑或未经请求的发散补充（触发歧义阻断或本协议第 4 条高危二次确认时除外）。
2. **资源缺位主动拦截（资源类）**：
   - **不凭空假设**：当执行任务缺少必要资源（如日志截屏、具体配置文件、环境 API、未暴露的结构体定义、权限密钥等）时，**必须立刻打断并向用户索取**。
   - **禁止虚构**：严禁自行伪造假日志、假配置或假接口返回值继续往下推导。
   - **状态取证优先（问答类）**：状态类问题（存在性/数量/取值/是否成立）必须先经工具取证再回答，证据不足时明说「未查证」，严禁凭印象或训练记忆作答；重复出现的机械判定优先沉淀为 toolbox 工具而非反复人肉执行。
3. **两次尝试熔断机制（难题/死锁类）**：
   - **硬性熔断**：针对同一个报错、测试失败或逻辑卡点，**连续尝试修正 2 次仍未解决时，必须立即停止修改**；用户补充新信息或明确指示继续后，计数重置。
   - **问题暴露格式**：第 3 轮禁止继续改代码，必须向用户输出以下卡点描述：
     1. `[已尝试方案]`：过去 2 次具体的修改与失败结果。
     2. `[核心卡点]`：当前无法突破的具体报错或矛盾点（附关键报错片段）。
     3. `[建议方向]`：提供 1~2 个需要用户决策或补充信息的可能排查方向。
   - **还原优先与长推理熔断（排错协议，薄指针）**：触发熔断、或问题属**重大故障**（核心功能不可用 / 构建测试大面积红 / 数据或契约受损）时，第 3 轮除卡点描述外同时提供「**还原优先**」选项；长排查/重大故障的完整协作协议——交接单格式、非阻塞接力循环（节拍/停滞触发/挂起/强制等待）、还原优先五步（锚定→沙盘推演→快照→可逆还原→变更复盘）、`[当前方案]` 置信度标尺、解决验收与快照退场、跨会话落盘——**SSOT 在 problem-triage §3**，触发后按其执行，严禁在此复述协议正文。
4. **隐性环境与破坏性隔离（环境类）**：
   - **假设显式化**：在涉及环境命令、依赖版本、操作系统特性的操作前，若未确定环境，先向用户确认或通过最轻量的命令探针确认，禁止假设环境。
   - **高危操作二次确认**：破坏性动作（如删除数据表、清空队列、强制覆盖分支）前，必须列出影响范围并等待用户显式授权。
5. **静态强约束（生成类）**：所有生成代码必须经本地工具链（compile / type-check / lint）校验后方可交付（无法校验时如实说明，严禁以「看着合理」替代），严禁引入不存在的 API 或类库；未经用户显式确认禁止引入新第三方依赖，优先复用项目已有工具类。
6. **契约保护（改动类）**：严禁隐式破坏现有公共接口与底层数据模型契约；大面积跨文件改动先列影响清单经确认再动手，有疑虑立刻停下确认。
7. **终端命令超时管控（防自动中断）**：
   - 长时运行命令必须给足超时：构建、测试、启动服务、批量脚本等长时任务统一使用 `timeout_ms` 300000~600000 毫秒（5~10 分钟）或更长，按任务预期时长设置，避免因默认超时导致进程被自动中断。
   - 命令执行过程中若发生报错，允许原样返回错误信息，但不允许在任务未完成前自动中断执行；只有用户明确要求停止时才终止进程。
   - 若不确定任务时长，优先取更长超时；若用户明确要求不中断，必须遵守该约束直到任务自然结束或用户人工取消。
8. **隐私拒存（安全类）**：密钥/令牌/口令/证书私钥等敏感数据严禁写入 `context/`（memory/devlog 随 git 入库，泄密即入历史）与任何代码或文档；用户不慎贴出的秘密不复述、不落盘，一句话提醒移入 `.env`（已 gitignore）或环境变量；发现已误写入 → 提示从文件删除，并提示该内容已进 git 历史、按需轮换密钥。

## 0. 目录结构 (Layout)

```
context/                      ← 可见目录，作为项目的一部分提交 git
├── CURRENT                   ← 当前绑定的大功能（个人指针，加入 .gitignore；日常默认 epic: misc，epic: none 仅明确停工时用，禁止空文件）
├── epics/                    ← 长期记忆 + 过程日志，按大功能（epic）组织
│   ├── misc/                 ← 常驻杂项 epic：散修/小改动统一挂靠，长成大功能则 ::bind 转正
│   └── <大功能名>/
│       ├── memory.md         ← 长期记忆 SSOT（决策/架构/进度 + 断点；会话恢复只读此文件）
│       ├── devlog.md        ← 开发过程日志（追加区，≥5 条自动归并进 memory.md）
│       └── todos.md         ← 域内待办（按需创建：首条域内条目时生成；格式归 memo-collector §0）
├── archive/                  ← 已完结 epic（memory 已提炼 ≤10 行，按需人工翻档）
├── todos.md / done.md        ← 全局备忘台账（misc/跨域/项目级兜底 + 完成列表；格式归 memo-collector §0）
├── pending-confirm.md        ← 多决策点确认台账（§2；台账非空时大动作冻结）
├── lessons.md                ← 项目经验总结（全局单文件，项目的一部分）
└── decisions.md              ← 决策洞察档案（::adr 写入；按 epic 分节 + misc 兜底；AI 只写不读，不进裁决链，历史不改写）
```

**文件头部声明 (File Header)**：所有记忆文件以固定 YAML 头部开头：

```yaml
---
dev-loop: memory | devlog | lessons | decisions
format: v1
epic: <大功能名 | global>      # lessons/decisions 为全局单文件，固定写 global
total-merged: <累计归并次数>
last-merge: <YYYY-MM-DD | none>
---
```

**头部维护规则（写死）**：
- 头部仅在**文件创建**与 **::merge 归并**时写入/更新（`total-merged` +1、`last-merge` 刷新）；追加轮**严禁触碰头部**；
- 头部**不含 pending 计数**——条目数始终由现实推导（§2 `tail | grep -c`），不缓存、零漂移；
- 会话恢复时先 `head -n 7` 校验文件角色与 epic 同 `context/CURRENT` 一致，再继续。

## 1. 动态输出策略 (Output Strategy)

修改代码时，按以下优先级执行，严禁主动打印未经修改的全量文件：

1. **Tool Edit 原地修改**：在 Write Profile 模式下，直接调用写/改文件工具更新目标代码（Token 消耗最低且零手动差错）。
2. **局部代码块 (Code Snippet)**：仅输出包含上下文改动的核心函数/类块，并标明文件路径与插入位置。
3. **降级 Unified Diff**：仅在用户显式要求或存在自动化 Apply Diff 工具时使用。

---

## 2. 日常交互与日志协议 (Protocol)

**任务分级 · 快车道（写死）**：仪式密度随影响面缩放——同时满足 ①改动 ≤2 文件 ②不涉 schema/命令协议/公共契约 ③意图明确无歧义 的**小改散修**走快车道：免评估/复述轮、免决策台账、文档（ui-spec 等）攒批补写，仅保留 devlog `[变更]/[验证]` 与断点刷新；验证按本节第 4 条分级执行。用户显式要求方案对齐/评估时照做（用户指令优先）；任一判据不满足即回标准流程；大需求/结构重构照旧走 dev-guide。

当本轮发生**任一触发**——产生业务代码/配置变更（Diff）、**解决了具备通用价值的 Bug**、显式推翻既有决策——Agent **必须用 Tool 追加对应日志**（对应下方第 1 / 2 / 3 条），严禁仅在聊天框文本回复：

1. **追加开发日志（devlog）**：调用写/改文件工具，将以下单行内容追加至 `context/epics/<大功能名>/devlog.md` 底部：
   `- [YYYY-MM-DD] [变更]: <1句话精炼说明完成的子任务/配置变更>`

2. **追加 Lesson 日志（仅限具备通用价值的 Bug，一旦满足即必记）**：若排查并解决了此类 Bug，调用工具追加至 `context/lessons.md` **底部追加区**：
   `- [<模块>] <报错现象> ➔ <根本原因> ➔ <避坑规则> (Ref: <大功能名>)`
   *（`lessons.md` 为双区结构：正文＝项目经验总结 SSOT（按模块归类的避坑规则），底部＝教训流水；排错轮次开始时应先读正文对照历史规则，再动手排查。**正文行禁用 `- [` 开头**——该前缀专属追加区，保证 grep 计数不被正文污染。）*

3. **SSOT 修正（决策推翻时强制，不依赖 Diff，双重动作）**：当用户显式推翻或废弃既有决策/结论时（即使本轮无任何代码变更）：
   ① **即时生效**：当轮用 Edit/sed 将 `memory.md` 正文中对应旧结论改写为新结论——**修正不等待归并**，消除「重置窗口缺口」，memory 恒为最新共识；
   ② **审计留痕**：向 `context/epics/<大功能名>/devlog.md` 底部追加 `- [YYYY-MM-DD] [SSOT 修正]: 旧结论 <X> 已废弃 ➔ 新结论 <Y>`（计入归并阈值）。

4. **验证账本（Diff 轮次强制，与 [变更] 成对）**：Diff 轮次收尾时随 [变更] 行追加验证账本行：
   `- [YYYY-MM-DD] [验证]: <实际执行的验证命令与结果，如 ./mvnw compile → 通过；tsc --noEmit → 通过>`
   未执行验证的如实写 `未执行: <原因>`，**严禁虚构验证**（对齐全局护栏 5）。**验证分级（写死）**：compile/lint（如 `flutter analyze` / `tsc --noEmit`）为每轮恒跑的最低门槛；全量测试仅在 ①数据层/动作层/命令协议变更 ②跨文件重构 ③提交收尾 时跑（纯 UI/文案轮跑相关测试文件即可）；docs-lint 仅 docs 变更轮——分级降噪不撤门禁，全绿声明可信度不变。[验证] 行计入归并阈值，归并时可压成 memory 一行「近期验证状态」（保留或丢弃最近一次，由归并判断）。::audit 第 12 项抽查 [变更] 与 [验证] 的差（「声称完成 vs 实际验证」缺口）。

**写码副作用标记（代码内，与日志并行）**：本轮写代码遇到「实现未实证」或「失败时猜测性兜底（空 catch / 只记日志 / 返回默认值）」时，按 `ai-sideeffect-guard §1` 在代码内留 `// UNCERTAIN:` / `// DEGRADE:` 标记（DEGRADE 须在兜底前打 `[DEGRADE] <场景key>` 日志）——标记**不落 devlog**、只随代码生存；四工具扫描与高危项处置口径见 `ai-sideeffect-guard §2`/§4（高危按 memo-collector 口径转 `风险` 待办）。

**多决策点确认台账（防悬空开工，写死）**：审计/方案/规划轮一次产出 **≥2 个需用户独立裁决的决策点**（冲突清单、方案选择、处置确认）时，严禁「用户部分作答 + 催开工」就让未决项悬空。**触发时机自执行（写死）**：产出决策点的**同一轮回复内**就完成「登记 + 抛出第 1 问」——回复结构固定为「决策点清单正文 → 末尾登记台账（写文件）→ 紧接着抛出 **[1/N]** 第一问（附背景+默认建议）」；严禁只出清单说「请逐条确认」就把动作交还给用户（这正是悬空之源），也严禁等用户先回复才登记。流程：
1. **登记**：全部决策点当轮落 `context/pending-confirm.md`（头部 `---` / `confirm: pending` / `format: v1` / `---`；条目行 `- [ ] [YYYY-MM-DD] <编号> <一句话问题>（不定则<后果>）`，按域分节可省——单 epic 场景平铺即可，**多 epic 并行期间必须按 epic 分节**（并行窗口待决项互不混，编号节内自编））；台账随 git 提交。
2. **引导（分级确认）**：决策点分两类——**裁决型**（互斥选项 / 大影响 / 有依赖）按编号**逐项串行确认**，一次只抛 1 个、等答案再抛下一个（严禁自答）；**复述确认型**（无互斥选项，仅对齐理解、防做反）可同轮**合并抛出全部**，用户一条回复批量确认。两类混杂时拆开：复述型合并前置、裁决型接着串行。每个决策点（无论哪类）都附**简要背景 + 默认建议选项**（可直接「同意默认」低负担推进，也可自答）；裁决型无依赖时按影响面从小到大排序（先易后难，前方决策可为后方提供上下文）；工具支持时用结构化选择题。
3. **部分确认**：已确认项**即时生效落盘**（决策写 memory/decisions/SSOT，不等问题集齐）；未确认项保持挂起——此时**大动作严禁开工**（Schema/契约/接口签名/结构重建/跨文件大面积改动），仅允许无争议取证与小修；每次回复必须显式列「未确认 N 项：<编号>」并继续引导剩余项。
4. **确认完毕**：全部确认后执行**综合分析**（冲突按裁决链收敛、方案统一定稿），决策一次落盘，清单文件条目清零（文件保留，复用）。
5. **可见性**：台账非空时 `::status` 附一行挂起提示；`::done` 收尾硬前置——台账未清零禁止收尾（决策未定 = epic 未真完结）。
6. **手动拆分指令 `::confirm`（用户显式触发）**：AI 漏走台账流程（只出决策点清单未登记、或把多个决策点混在一个问题里）时，用户发 `::confirm` → AI 补登记（`context/pending-confirm.md` 写入全部决策点）→ 按 §2 分级口径从 `[1/N]` 开始确认。`::confirm <事项>` 带参数时仅登记该事项为单条台账并立即抛问。

**收尾 Git 指令建议（生成不执行）**：产生 Diff 的轮次收尾时，回复末尾附一段 git 指令建议代码块——基于本轮实际改动文件生成 `git add <文件清单>`（含本轮落盘的 context/ 记忆文件）+ `git commit -m "<一句话说明>"`（措辞参照本轮 devlog 行），块首标注「建议指令，未执行」；**严禁代跑任何 git 写操作**（add/commit/分支/推送一律由用户复制执行）；分支级操作（建分支/合并/切换）仅在用户明示要求时生成；无 Diff 轮次不生成。部署属项目池脚本职责（如 deploy-cloud-run），不在本建议范围。

*(豁免规则：以下轮次**禁止追加任何日志**——① **未产出可留存结论的**纯咨询/排错轮次；② 执行 `::merge`、`::bind` 等协议操作的轮次；③ 除 Lesson / SSOT 修正落盘外，仅维护 `context/` 文档本身的轮次（含日志追加自身产生的写入，防递归记日志）。)*

**不受豁免（即使无代码 Diff 也必须落盘）**：解决了具备通用价值 Bug 的排错轮次 → 记 Lesson；推翻既有决策的轮次 → 记 SSOT 修正。

**实现口径（写死，防会话间漂移）**：
- **追加**：优先用全局工具 `toolbox run devlog <change|verify|note|lesson> <epic> <文本>`（单行构造/格式防呆/幂等去重内聚在工具里，`--json` 预检不落盘、`--self-test` 自测）——toolbox 未初始化或工具缺失时降级终端 `cat >> <目标文件> <<'EOF'` + 单行日志 + `EOF`，一次调用完成；**严禁先整读再重写**（成本随文件增长线性变贵）。终端不可用时降级：Read 仅取尾部若干行 → Edit 锚定原末行追加。日志行内避免 `${...}` 字面量（终端静态扫描会拒），必要时只写属性名。
- **断点刷新**：优先 `toolbox run devlog bp <epic> <文本>`（单趟替换+重复去重+章节缺失重建+恒 1 行校验，幂等）——工具缺失时降级 sed：`sed -i 's|^- \[断点\].*|- [断点] 下一步：<新内容>|' <memory.md> && grep -c '^- \[断点\]' <memory.md>`（sed 匹配零行会**静默成功**，必须以 grep 校验，非 1 即异常）。断点行重复/章节损坏的机械修复用文件级维护工具 `toolbox run breakpoint check|fix <memory.md>`（get/set/check/fix 四子命令）。
- **记账单一事实源**：进度事实**只追加 devlog**；memory 正文仅在 ①§4 归并 ②`::remember` ③SSOT 修正 时写入，断点 sed 是 memory 唯一的日常写入点——严禁每轮把进度同时双写 devlog+memory（双写绕过归并去重，memory 单向膨胀）。同一文件同一轮只用一种编辑工具（Edit 或 sed 二选一，混用触发文件状态校验失败返工）。
- **计数（低频校验，非每轮）**：本窗口上下文即短期计数——Agent 可见本窗口内已追加的日志轮数，**不必每轮实数计数**；仅在 ① 恢复后首轮 ② 上下文计数已近/达阈值 ③ 长窗口或不确定时，用 `tail -n 20 <目标文件> | grep -c '^- \['` 做一次实数校验。严禁整文件 Read 数条目。

## 3. 状态自恢复与绑定协议 (Bootstrap & Binding)

- **状态恢复**：新会话开场（或 Cmd+R / Ctrl+R 重置后），Agent 优先调用工具读取项目根目录 `context/CURRENT`（内容格式：`epic: <大功能名>`），随后**只读 `context/epics/<大功能名>/memory.md`（蒸馏后的长期记忆与断点）**即可恢复共识——不读 devlog、不依赖对话历史（可先 `head -n 7` 校验头部角色/epic 与 CURRENT 一致）。**排查交接例外（写死）**：memory 读取后对绑定 epic 的 devlog 执行一次 `tail -n 20 | grep '\[排查交接\]'`——命中即续读该尾部并按交接单（problem-triage §3.1）续上排查（长排查中途重置的唯一续接通道），未命中仍不读 devlog。**恢复时台账联动**：`context/pending-confirm.md` 存在且有未清条目 → 开场附一行挂起提示（未确认编号清单）并优先引导确认，台账清零前大动作维持冻结（§2 多决策点确认台账）。**若 CURRENT 为 `epic: none` 或文件缺失**（新机器 clone 后的常态——CURRENT 被 gitignore）：视同无活跃 epic，仅提示用户 `::file` 绑定，严禁自行挑选开工；**CURRENT 指向的 epic 目录不存在或头部校验失配**：以 `ls context/epics/` 实际目录为准列出候选、提示重新 `::file` 绑定，严禁自行猜绑。
- **会话绑定（开场初始化，写死）**：恢复流完成后输出**会话绑定卡**（≤4 行，数据源 `toolbox run panel`，脚本缺失降级手推）：
  ```
  会话绑定 ｜ dev ｜ 类型: epic 大需求（建议挂 dev-guide）
  挂载: ▶ e2ee-auth（CURRENT 一致）→ memory.md / devlog.md
  任务: e2ee-auth(10-02)▶ payment-refactor(09-25) ｜ 多任务切换 ::board
  状态: 断点 下一步：完成重连握手 ｜ 待决 2（大动作冻结）｜ 待归并 3 ｜ 债 U0 D1 P0（粗计数，--debt 明细）
  ```
  ① **域**：本 skill 加载即 dev；② **类型**：CURRENT 为 `misc` → 散修（快车道默认、建议挂 misc 口径），非 misc → epic 主线（大需求/结构重构建议加载 dev-guide），用户首句显式声明（如「这窗口专做排错」）时按声明标注；③ **挂载**：▶ 绑定 epic 与其 `memory.md`/`devlog.md` 状态文件对，含与 CURRENT 的一致性核对（多窗口失配时提示重绑，并行窗口纪律 ④）；④ **任务行**：panel 任务活动表原样带上（多会话并行感知——开窗即见全部任务与最后活动），切换走 `::board`；⑤ **状态**：断点 + 待决（>0 注明大动作冻结，台账联动 §2）+ 待归并 + 债（U/D/P 粗计数＝UNCERTAIN/DEGRADE/PATCH 标记数——实现层债的常显位，让人在只做决策时也不丢实现细节；非零时建议动作可含 `panel --debt` 取明细或按 ai-sideeffect-guard §2 跑对应扫描；粗计数不含白名单/形状过滤，0 ≠ 无隐患）+ 并行（panel「并行:」行在场时提示区**必含**「恢复请点名任务」——多任务交错期点名恢复，CURRENT 仅最近绑定，禁裸奔「继续」默认开工）。绑定卡是恢复的收尾输出，不是新指令——严禁为出卡单独询问用户。
- **绑定纪律（会话期，写死）**：绑定确立后，本会话的日志追加、断点刷新、SSOT 修正**只落绑定挂载点**；换绑走 `::bind`（切走先归并）；插做其他 epic 成规模工作先切绑（并行窗口纪律 ③）；**类型只定挂载与流程入口，仪式密度仍按 §2 逐轮分级**（类型非逐轮豁免依据）。
- **开场环境检查（agent-toolbox，fail-open）**：若 shim `~/.local/bin/toolbox` 或 `~/.agents/toolbox/` 存在，开场读 CURRENT 前先执行 `toolbox run-hooks bootstrap --quiet`：exit 0 静默继续；非 0（工具 FAIL/自身故障）**严禁阻塞恢复流程**，仅在开场回复末尾附一行 ⚠ 提示（FAIL 明细按 memo-collector 口径转 `风险` 待办；`--quiet` 无输出，需明细再裸跑一次不带 `--quiet` 的同命令）。未初始化 toolbox 的环境直接跳过本项。ZCode 用户级开场协议（`~/.zcode/AGENTS.md`）已内嵌本钩子——同窗口不重复执行。
- **断点指针 (Checkpoint)**：`memory.md` 正文末尾固定维护 `## 断点` 章节，内容恒为一行：`- [断点] 下一步：<具体子任务>`（无待办时写 `等待新子任务`，**严禁留空或过期**）。它是唯一**不可由文件推导**的状态（下一步意图），故必须显式维护。维护规则：任何使「下一步」改变的轮次（Diff / SSOT 修正 / 结论性咨询）收尾时刷新；实现优先 `toolbox run devlog bp <epic> <文本>`（单趟替换+重复去重+章节缺失重建+恒 1 行校验，幂等）——工具缺失时降级 sed `sed -i 's|^- \[断点\].*|- [断点] 下一步：<新内容>|' <memory.md> && grep -c '^- \[断点\]' <memory.md>`（sed 匹配零行会**静默成功**，必须以 grep 结果校验，**非 1 即异常**：0 ＝ 章节缺失→重建 `## 断点`＋断点行；>1 ＝ 重复→去重保留最新；内容含特殊字符时改用 Edit 锚定该行）。恢复收益：读 CURRENT（槽位）+ 读 memory（结论＋断点）→ 直接开工，恢复从「推断」变「查表」，开场白可简化为「继续」。
- **绑定与切换**：当用户发送 `::file <大功能名>` 或 `::bind <大功能名>` 时（忽略路径与后缀，只取大功能名），机械件统一走 `toolbox run mount-init`——切换/续绑 `--current-only --epic <名>`，完整挂载 `--epic <名> --doc <文档>`：骨架创建（memory.md 含 §0 头部 + `## 断点` 初始行 `- [断点] 下一步：等待拆解`、devlog.md）、CURRENT 改写、切换前置（旧 epic devlog 未归并先 §4 归并）与防覆盖校验由脚本机械执行并拦截，**Agent 严禁手拼骨架文件**；脚本不可用时才降级手工（同口径创建）。完成后极简确认绑定成功，并按任务形态附一行提示：大需求/复杂迭代建议加载 dev-guide 按流程骨架推进；散修挂 misc 即可，不推流程。**裸调用（`::file` 无参数）**：只读列出 `ls context/epics/` 候选与当前绑定，提示选择，不写任何文件。
- **并行窗口纪律（多任务并行，写死）**：CURRENT 是全项目单指针，多窗口并行时不可作「本窗口在做什么」的依据——按**一窗口一 epic** 隔离：① 每个并行窗口开工即 `::bind` 到本窗口主战场，绑定即本窗口锚点；② 并行窗口绑不同 epic，**同 epic 严禁双窗口同时写**（devlog 追加交错、断点 sed 互相覆盖，恢复共识失真）；③ 窗口内插入其他 epic 的成规模工作前必须先切绑（零星散修照旧挂 misc 不算混轮，连续多轮按转正口径处理）；④ 多窗口并行期间恢复后「继续」前先核对 CURRENT 与本窗口任务一致，不符先 `::bind`（单窗口单任务维持现有恢复流，零额外摩擦；panel「并行:」行是本条的机械触发信号——行在场即多任务交错活跃期）；⑤ 并行窗口改同一批代码文件属 git 层冲突面，建议分支/worktree 隔离，本纪律只保记忆不混；⑥ **越界失败自动暂停（写死）**：测试/构建失败且归因落在**本会话边界之外**——失败文件 ∉ 本会话 diff（`git status --short`/`diff --name-only`），且与本人改动无因果链（接口/签名/契约未触及失败模块）——**立即暂停**：严禁修改边界外文件（含「顺手修绿」），devlog 记 `[note]` 暂停行 + 断点刷新为「等待用户指令：<失败摘要>，初判 <疑似来源> 外部成因」，输出卡点三要素（失败摘要/归因证据/建议方向）后等待；**仅用户下一步指令显式授权**（修那边 / 忽略继续 / 确认与己无关继续等）方可继续。归因存疑（可能与己有关）不适用本条，走正常排错与护栏 3 熔断；边界归属查 project-index 索引与 `::board` 最近活动；单窗口同理（发现非本任务模块损坏，同样不越界修复）。多任务全景与选择入口见 `::board`（§6）。
- **文档挂载纪律（::bind，写死）**：正式 epic 必须挂底子文档——`::bind` 先跑 `toolbox run panel --mounts` 取**候选列表 + 挂载对照**（`deprecated` 墓碑不可挂；▶已挂 = 该文档已有 epic，续绑或归档重开），**epic 名 = 文档 slug**，骨架 memory.md 正文首部加一行 `- [挂载] <路径>`；候选空/不合适 → 亮牌先建底子文档再挂载（初稿提炼自需求讨论、严禁占位文案；冷 bind 走反向采访），一次确认「建文档 + 建 epic」。选定后机械件跑 `toolbox run mount-init --epic <名> --doc <文档>`（候选空加 `--create-doc` 连底子文档骨架一并创建，首稿内容仍由 AI 本轮提炼落盘）——slug 一致/墓碑/重复挂载/切换前置由脚本机械拦截。**内容/状态分工**：底子文档 = 内容 SSOT（需求/设计/定稿/实现方式即写即落，方案权衡走 ::adr 落 decisions.md），memory 只记状态与指针，严禁把文档内容抄进 memory；misc 散修不挂载、流程不变；存量 epic 缺挂载行不强制补（::audit 提示级）。
- **杂项挂靠 (misc)**：散修/小改动（不够格建正式 epic）统一挂靠常驻的 `context/epics/misc/`——日志直接落 `misc/devlog.md`，**不要求为此切换 CURRENT**（挂靠点由任务性质决定，CURRENT 只记主战场）；CURRENT 日常默认 `epic: misc`（散修轮次同样走 §2 日志协议，lessons 记 `Ref: misc`）；misc 内散修若长成大功能（连续多轮），`::bind <新名>` 转正（挂载纪律同上），misc memory 归并时只留一行「已转正为 <新名>」索引，日志不搬家；misc 断点恒为「等待散修任务」。
- **自动重构 (Auto-Refactor)**：本轮日志追加完成后，Agent 以**上下文短期计数**判断是否近阈值（恢复后首轮、长窗口或不确定时，按 §2 实现口径实数校验一次），**本轮追加目标的 `devlog.md`（含 misc 挂靠）**与 `lessons.md` **任一 ≥ 5 条**即在本轮末尾**针对该目标 epic 自动执行 §4 双文件压缩**（无需用户触发），并在回答末尾附注一行：
  > ⚙️ **[自动重构完成]**：追加日志已归零压缩（阈值触发）。建议方便时 Cmd+R / Ctrl+R 重置窗口。

- **写入纪律（引用 §2 记账单一事实源）**：本层只读取/绑定，绝不手改 memory 正文——memory 唯一日常写入是 §2 断点 sed，正文写入仅走 ①§4 归并 ②`::remember` ③SSOT 修正 三通道；同一文件同一轮只用一种编辑工具（Edit 或 sed 二选一，混用触发文件状态校验失败返工）。

## 4. 重构与归纳 (Compression Procedure)

**触发方式有二**：① **自动**——§3 阈值达成时本轮末尾自动执行；② **手动**——用户随时发送 `::merge`。两者执行同一套**双文件压缩**流程：

1. **大功能长期记忆（memory.md）**：将 `context/epics/<大功能名>/devlog.md` 底部的碎片化日志提炼归纳进 `memory.md` 正文（SSOT），并清空 devlog 追加区；**两文件头部同步更新**（`total-merged` +1、`last-merge` 刷新，按 §0 规则）；重写时 `## 断点` 章节原样保留最新值。**`[SSOT 修正]` 条目拥有最高归纳优先级：必须以其覆盖正文中对应的旧结论，严禁新旧并存**（修正已按 §2 当轮即时生效，此处仅为兜底）。
2. **项目经验总结（context/lessons.md，全局单文件）**：将其底部追加区的教训流水去重、合并同模式、按模块归纳进正文（项目级避坑规则 SSOT），并清空底部追加区；头部同步更新（`total-merged` +1、`last-merge` 刷新）；`[SSOT 修正]` 优先级规则同样适用。
3. **极简回复**：完成后，仅回复（自动触发时为附注）一行：
  > *"已完成 `<大功能名>` 记忆归并（devlog → memory.md）与 `lessons.md` 重构，追加日志已归零压缩。请按 Cmd+R / Ctrl+R 重置窗口。"*

*（`context/` 整体作为项目的一部分提交 git（仅 `CURRENT` 为个人指针，加入 `.gitignore`）：自动压缩均可回溯，归纳失真时细节可从历史找回。**git 冲突面**：append-only 的 devlog 走合并无痛；`memory.md` / `lessons.md` 为编辑型文件，多机或多端同时归并必然冲突且发生在提炼后的正文上——单人多机需「切换机器前 commit」纪律，团队协作时此为已知取舍。**软上限**：`memory.md` 正文超过 ~150 行时，应考虑该 epic 收尾归档或拆分为新 epic，恢复成本随正文缓慢上升。）*

---

**归并事故回滚（灾难恢复纪律）**：归并或记忆写入导致 memory.md / lessons.md 质量断崖式下跌时，严禁 Agent 自行重写修复——`git checkout -- <文件>` 恢复最近提交版本，报告事故经过，由人工微调补记（前提：context/ 除 CURRENT 全量入 git；devlog append-only 一般无需回滚）。

## 5. 实测闭环验证 (1 分钟，dev-init 接入时跑一次)

`::file <名>` → 确认骨架创建与 CURRENT 写入 → 重置窗口 → 发「读 context/CURRENT，开始：[子任务]」→ 成功标准：不追问绑定、直接按 memory 断点开工；代码变更日志落 devlog 而非聊天框。

## 6. 附属指令流程 (Manual Ops)

- **`::remember <事实>`（人工记忆入口）**：结论**直接写入 memory.md 正文**（用户主动发起即视为已确认）；若影响下一步，同轮刷新断点。**不写 devlog**——已直入 SSOT。
- **`::adr <标题>`（决策洞察档案）**：本窗口敲定的方案权衡以多行条目落 `context/decisions.md`——**按 epic 分节 + `## misc` 常驻兜底**（节不存在时锚 `## misc` 上方插入，`## misc` 恒最后一节；节内最新在上）。条目格式（写死）：`### [YYYY-MM-DD] <标题> (src: ai | 用户)` + 四段——场景/痛点、可选方案（含否决理由）、最终决定、AI 洞察。**定位护栏**：decisions.md 是历史档案非权威——不进裁决链（memory 冲突以 memory 为准）、SSOT 修正与归并不回改（历史不改写）、恢复不读（AI 只写不读）。落盘同轮二选一显式留痕：约束后续工作 → 经 `::remember` 写入 memory；不约束 → 尾标 `（不约束后续工作）`——严禁不表态（::audit 第 9 项对账兜底）。
- **`::next [方向]`（断点规划）**：① 断点明确且未过期 → 报告内容，确认是否开工；② 断点为空/`等待拆解`/已过期 → 读 memory 正文 + `tail -n 20` devlog，推导候选子任务（**≤3 个，各一行理由**），用户选定或默认第一项 → 按 §3 口径写入断点并校验 → 开工。**严禁复述 memory 全文、严禁超出 3 候选**——规划结果必须落盘为断点，否则本轮规划等于白聊。
- **`::board`（任务看板，多任务并行选择入口）**：跑 `toolbox run panel --board` 取逐任务表（`<epic> ｜ 最后活动 <日期> ｜ 断点：<内容>`，当前绑定标 ▶，misc 标「常驻」，archive/ 不列，按最后活动降序），按下方「面板判读协议」渲染，**末尾固定附一行跨 AI 恢复咒语**：`其他 AI/工具：读 context/epics/<任务名>/memory.md 按断点继续`。只读不写；用户选定后走 `::bind` 正常绑定流程。
- **`::status`（运行态快照）**：一条调用链返回——CURRENT 内容、断点行、devlog（绑定 epic 与 misc 两处）与 lessons 待归并计数（`tail -n 20 | grep -c '^- \['`）、`wc -l` memory 行数。**只读不写，输出 ≤5 行**。
- **`::help`（面板入口，求助第一句）**：跑 `toolbox run panel` 取事实块（绑定/断点/任务活动/计数），按下方「面板判读协议」渲染四区——**我在哪 / 现状 / 建议动作 / 按意图命令速查**（速查一行分组即可，全量命令清单含含义仅用户显式索要时经 `toolbox run cmds` 收集输出，cmds 缺失降级读 COMMANDS.md）；新会话 / 跨 IDE 求助入口；排错协作时附一行「人类侧排错说明：`problem-triage/manual.md`」。
- **面板判读协议（::help / ::board 共用，写死）**：① **事实以脚本为唯一来源**——跑 `toolbox run panel` 后严禁再 grep/读文件重复取证；脚本缺失（未入池环境）才降级手推（board 用 ls+grep 现场推导口径）；panel 自身故障（exit 2）时可改跑轻量 `toolbox run ctx-status`（仅 ::status 数据面）；② 事实块**原样嵌入**，数字/日期严禁改写或凭印象修正，数据可疑重跑脚本，不手改；③ **建议动作由 AI 结合本窗口语境自产**（≤3 条，有信号才写、无信号不凑数）——机建议位暂留空，稳定复现的建议按 §8 收敛复盘口径逐步固化进脚本；④ 追问按需 `toolbox run panel --deep <epic>` 单点取数（债面追问用 `panel --debt`：标记分布 top 文件 + 白名单 + 上次体检时效），不做全量深挖；⑤ 常态回复 ≤10 行；面板只读只建议，执行仍走 §9 触发纪律；⑥ **字段同步**：panel 输出字段增删的当轮，同步依赖它的卡模板（§3 绑定卡）——panel 改字段与卡模板改字段是同一轮义务。

## 7. 审计与质检 (Audit)

**触发**：① `::audit` 手动；② `::done` 第一步**强制执行**；③ 建议时机：多机同步/分支切换后、久别重置恢复后。**机械项可选预填**：先跑 `toolbox run ctx-audit --root <项目根>`（委托 context-lint 代跑机械项，人判项标 ❓ 交 AI 补判），按其结果逐项输出 ✓/⚠——清单语义以本节为唯一事实源，脚本仅是执行器；脚本缺失时照常手工逐项。

**清单（12 项）**（逐项一行输出 `✓ / ⚠ + 动作建议`）：

1. **断点新鲜度**：`grep -n '^- \[断点\]' memory.md` 对照 devlog 尾部——已被完成工作超越即 ⚠，转 `::next` 重写；
2. **新旧并存**：通读 memory 正文，同主题残留多条矛盾结论即 ⚠，按 `[SSOT 修正]` 优先级当场收敛；
3. **devlog 积压高价值项**：devlog 存在未归并的 `[SSOT 修正]` 即 ⚠，**立即执行 §4 归并**（堵重置复活缺口）；
4. **记忆补记审查**：对照本窗口结论与 memory 正文——「聊定了但没落盘」的决策即 ⚠，经确认按 `::remember` 口径补写（记忆库自查生长，对应插件的回合内记忆审查，此处为手动低频触发）；
5. **lessons 与规范去重**：对照现有规范 skill 清单，已被覆盖的正文条目降级为一行 `Ref:`；
6. **尺寸健康**：`wc -l` 三文件，memory 正文 >150 行 ⚠ 建议收尾或拆分（§4 软上限）；
7. **孤儿 epic**：`ls context/epics/` 对照 CURRENT 与各 devlog 修改时间，长期未动者提示 `::done` 或确认搁置（**misc 为常驻挂靠，不算孤儿**）；
8. **头部校验**：`head -n 7` 各记忆文件，字段缺失/角色与目录不符即 ⚠；
9. **指针抽查**：grep 各薄指针（COMMANDS.md 命令手册、dev-guide §3 命令速查、项目索引关联行）与各 memory.md 挂载行（路径存在、非 deprecated 墓碑；机械项由 audit 钩 context-lint 挂载面代跑）的锚点串是否在目标文件真实存在——不存在即 ⚠，当场修指针；改过其他 skill 节号/节名后必查（引用方含 COMMANDS.md），例行审计抽查 2~3 条控成本。另含 **decisions↔memory 契约对账**：decisions.md 各节最新 1~2 条在对应 epic 的 memory 正文有无约束型契约行——缺失即 ⚠，经确认补 `::remember`（::adr 单向联动无写入校验，此处兜底）。project-local skill 对代码现实的锚点存在性（路径/命令/类名 FQN）可跑 `toolbox run skill-verify` 代跑（机械半边，语义核实留 AI）。
10. **skill 卫生抽查（事实指针化）**：规范类 skill 正文严禁自带易漂移事实（模块结构/领域清单/编译命令/依赖版本号/环境限制），一律指针到项目事实源（workflow 类 skill、项目索引），grep 抽查疑似事实锚点，正文自带非指针出处即 ⚠ 当场改写；description 是路由触发信号非正文，只留项目锚点+技术栈+高频症状关键词，细节沉正文。新增 skill 或改过事实性段落后必查，例行抽查 2~3 条控成本。
11. **toolbox 巡检（agent-toolbox）**：toolbox 已初始化（`~/.agents/toolbox/` 存在）时执行 `toolbox run-hooks audit --quiet`——**以退出码判定**：exit 0 = ✓，exit 1 = ⚠（`--quiet` 静默一切输出，只看退出码；需 FAIL/ERROR 明细时再跑不带 `--quiet` 的 `toolbox run-hooks audit`，或 `toolbox run cl` 裸跑），按 memo-collector 口径转 `风险` 待办；空池/未初始化直接 ✓ 跳过；
12. **验证缺口抽查**：grep devlog 尾部最近 2~3 条 `[变更]` 行是否各有同日 `[验证]` 账本行——[变更] 无 [验证]、或 [验证] 写「未执行」无理由即 ⚠，补验证或确认补因；人工抽查（机械化待办，口径同第 9/10 项）。

**修复纪律**：琐碎修复（归并积压、补记、降级 Ref、重写断点）列清单经确认当场执行；结构性修复（拆分、归档）转 `::done` 或用户决策。**审计轮不追加任何日志**（豁免规则适用）。

**`::verify <epic|lessons|all>`（账实对账）**：上方十二项是**账账相符**（记忆与 skill 文档内部一致）；verify 验**账实相符**（记忆 vs 代码现实）——裁决链已把 memory 抬到最高权威，无验真机制即裸奔。
- **范围钳制**：仅验可机械定位的断言（引用具体类名/路径/属性/阈值/开关的结论）；抽象理由/偏好一律标 ❓ 交人工，不猜测。
- **三态输出**（≤15 行）：`✅ 仍成立` / `❌ 已失效（附代码证据行）` / `❓ 无法机械验证`。
- **修复路径**：❌ 项提议**批量 `[SSOT 修正]`**（memory / lessons 各走 §2 对应通道），经用户确认落盘；lessons 失效规则优先修——过期教训会误导未来每一轮排错。
- **建议时机**：里程碑收尾、久别重开、`lessons.md` 归并出新规则后（趁热验真）、起疑时。仅用户显式触发。

## 8. epic 收尾 (Closure)

- **`::done`**（**misc 常驻，不适用收尾**）：第一步**强制执行 §7 审计，存在 ⚠ 项即中止收尾、先修复**；通过后执行**收敛复盘**（升舱后输出一行度量，见下）；随后**待办先处置清零**（memo-collector §4：完成流转/转全局/删除，经确认，`epics/<名>/todos.md` 随目录归档）；再将 memory.md 提炼为 **≤10 行结论块**（保留头部与 `## 断点` 改写为完结说明），目录移入 `context/archive/<名>/`，`decisions.md` 中该 epic 节若有条目则整体移入 `context/archive/<名>/decisions.md` 并删除该节，`CURRENT` 改写为 `epic: none`，一行回复确认。收尾后该 epic 退出活跃集，恢复流程永不再读它（按需人工翻档）。

**收敛复盘（::done 内置，升舱 L2→L3）**：收尾时逐项核对——① lessons 正文中已被验证多次、表述稳定的条目 → 提议固化进规范/事实源 skill（原条目降级一行 `Ref:`，对齐 §7 第 5 项口径）；② devlog/待办中同类澄清 ≥2 次的约束 → 按 memo-collector「咒语」行固化信号提议升级事实源；③ todos 中 `[long]` 条目按 memo-collector §4 重评；④ ::verify 近期 ❌ 项确认已批量 SSOT 修正。全部走「提议 → 用户确认 → 落位」，AI 不静默改写 skill。收尾回复附一行**收敛度量**：`收敛: +N 固化 / M 待定 → 事实源`（N=本轮升舱条数，M=仍留 L2 的条数）——跨 epic 观察趋势，固化递增、待定递减即体系在收敛。

## 9. 指令总表 (Command Surface)

**指令体一律薄指针（「执行 §X」），流程正文全 skill 只此一份**——哪条指令开始自带全文，哪条就是漂移的开始。

| 指令 | 职责 | 指向 |
|---|---|---|
| `::file` `::bind` | 绑定/切换（文档锚定：候选选底子文档，名=slug；切走先归并旧 epic） | §3 |
| `::remember` `::next` `::status` `::board` | 记忆入口 / 断点规划 / 快照 / 任务看板（并行选择入口） | §6 |
| `::adr` | 决策洞察档案（权衡详存，AI 只写不读） | §6 |
| `::confirm [事项]` | 手动触发决策点拆分登记 + 分级确认（AI 漏走台账流程时的兜底） | §2 台账第 6 条 |
| `::merge` | 手动归并（§3 自动触发的覆盖口） | §4 |
| `::audit` `::verify` | 十二项质检（账账）/ 记忆对现实（账实） | §7 |
| `::done` | epic 收尾（内含审计） | §8 |
| `::help` | 面板（panel 事实块 + AI 判读渲染，求助入口）；排错协作时附一行「人类侧排错说明：`problem-triage/manual.md`」 | §6 |

**分工**：干活归自动化（日志追加、≥5 归并协议自走）；指令只管自动化覆盖不了的三类时刻——**人工判断**（::remember、::adr、::done）、**规划决策**（::next）、**系统健康**（::status、::audit、::verify）。

**跨 skill 速查**：构建/验证/lint 等项目专属命令见当前项目 project-local 索引「命令速查」节（机制见 project-index）——本表只覆盖本 skill 的指令面。

**触发纪律**：全部指令仅用户显式触发；Agent 严禁自主执行 `::audit` / `::verify` / `::done`；一切修复经确认后落盘。
