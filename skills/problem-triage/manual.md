# 排错说明书（给人类用户）

> **这是什么**：当 AI 在排查重大/疑难问题时，会按 dev-loop 护栏 3 的协议与你协作。这份说明书告诉你：**AI 会给你什么、你该做什么、哪些红线是你必须守的**。遇到交接时按本文对照执行即可，无需记住 AI 侧的任何规则。

## 1. 你会收到什么

AI 停止闷头排查时，会向你抛一份**三行交接单**：

```
[已排除]      已证实不成立的假设（各附证据）——不用再怀疑这些方向
[待验证假设]   当前最可能的 1~3 个错误方向，每条标注侧别
[需要用户]     具体到可直接执行的资源/操作/决策请求
```

同时你会知道当前处于哪条路径：

| 场景 | AI 的动作 | 你的角色 |
|---|---|---|
| **重大故障**（核心功能不可用/大面积红/数据契约受损） | 首轮即声明「将分段推进」，每段输出进展 | 关注各段进展，在决策点表态 |
| **熔断**（同一问题修 2 次失败） | 输出卡点描述 + 提供「还原优先」选项 | 决定：继续排查 or 还原 |
| **长排查停滞**（连续 3 轮无新信息） | 停止推理，抛三行交接单 | 按第 3 节响应 |

## 2. 如果选择「还原优先」：四步流程与你的决策点

1. **锚定正常版本**：AI 会提议候选（最近验证通过的 commit / 手工 tag / 你确认过的时间点）——**「最后一次正常」以你的口述为准**，AI 提议的候选必须经你确认才执行；
2. **快照现场**：AI 先固化故障态再还原（排查证据不丢），此步无需你操作；
3. **可逆还原**：AI 只用可回退手段（`git revert`/快照重建）；**`reset --hard`、`clean -f` 等不可恢复命令默认禁用**——若 AI 请求执行这类命令，属于高危授权，确认影响范围后再批；
4. **变更复盘出方案**：AI 对比「正常版本..故障快照」的 diff——**你会在动手修复前收到复盘结论与方案**，不会先斩后奏。
   - diff 相关 → 给出针对性修复方案，等你确认；
   - diff 无关 → 转向八侧排查（见第 4 节），不会在原改动上缠斗。

## 3. 收到交接单后，你怎么响应

**第一步：读 `[待验证假设]` 的侧别标注**——每条假设尾部标了 `(代码侧|数据侧|环境侧|时序侧|意图侧|第三方侧|资源侧|发布侧)`，侧别告诉你该准备什么背景。

**第二步：按侧别准备入场背景**：

| 侧别 | 你要准备什么 |
|---|---|
| 代码侧 | 最近变更的业务动机（AI 会自查 commit/devlog，缺的才问你） |
| 数据侧 | DB 访问途径或代跑查询、迁移记录、受影响的用户/记录范围 |
| 环境侧 | 各环境配置实际值、部署时间线；**或直接代执行复杂环境操作**（见第 5 节） |
| 时序侧 | 复现步骤、高峰时段信息、代取运行时日志 |
| 意图侧 | **重新说清真实意图与验收标准**——这类问题排查解决不了，只能对齐 |
| 第三方侧 | 平台状态页结论、账号/配额面板截图、工单渠道 |
| 资源侧 | 监控曲线（CPU/内存/磁盘/QPS）、告警记录 |
| 发布侧 | 流水线状态、线上实际制品版本、回滚记录 |

**第三步：响应 `[需要用户]`**——里面的每条都是可执行的（哪段日志、哪个环境、什么权限、什么决策），做完回传结果即可。**模糊请求可以直接打回**（协议禁止 AI 抛「帮我看看」）。

**意图侧特别注意**：若你看到 `(意图侧)` 标注，说明 AI 怀疑「实现的是错误的理解」——此刻最有效的动作是**一句话重述你的真实预期**，而不是提供任何技术信息。

## 4. 八侧速查（判断问题大概在哪）

```
代码侧   diff 能对上（改错/逻辑错/旧写法/修 A 坏 B/契约破坏）
数据侧   存量数据坏：脏数据/迁移半途/旧格式缓存 —— diff 查不出
环境侧   同码不同环境行为不同：依赖/配置/开关漂移
时序侧   间歇性：竞态/缓存击穿/顺序依赖 —— 需运行时证据
意图侧   技术全对但不是你要的 —— 只能问人
第三方侧 错误来自外部：风控/密钥过期/配额/对方改协议
资源侧   随负载恶化、重启缓解：OOM/磁盘/连接池/QPS
发布侧   线上跑的不是你以为的代码：部署半截/旧制品/回滚不完整
```

**发布侧特别提醒**：如果你发现「线上行为与本地同 commit 不符」，主动说「检查一下发布」——这是最容易被 AI 误导向环境侧空转的一类。

## 5. 你的三条红线（AI 不会越过，但你要知道）

1. **不可恢复的 git 操作**（reset --hard / clean -f / 强推）必须你显式授权具体命令；
2. **生产/数据破坏性操作**（删表/清队列/覆盖分支）必须列影响范围后等你批准；
3. **AI 只给步骤不硬试不可达环境**：生产变更、内网调试这类操作，AI 会给你操作步骤与预期输出，由你执行后回传结果——回传时带上原样输出，别只说「成功了/失败了」。

## 6. 一图总览

```
问题发生
  ├─ 小问题 → 常规修复（你正常下指令即可，无特殊流程）
  └─ 重大/疑难 → AI 声明分段推进
        ├─ 修 2 次失败 → 熔断：卡点报告 + 「还原优先？」→ 你选
        │      └─ 选还原 → 锚定(你确认) → 快照 → 可逆还原 → diff 复盘 → 方案给你确认
        └─ 排查 3 轮无新信息 → 三行交接单（已排除/假设+侧别/需要你）
               └─ 你按侧别备背景、响应资源请求 → 结果回传 → AI 继续
                     └─ 又停滞 → 回到交接单再抛（不会在同一假设上空转）
```

> 全程你只需要做三类事：**确认锚点、提供人侧独有的信息/操作、在方案上拍板**。其余（自查、推导、可逆操作）AI 负责且不会让你重复劳动。
