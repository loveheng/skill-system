# problem-triage · 问题八侧分流（人类排查者的背景说明书）

> **定位**：问题分类是给人看的——AI 推理不依赖分类，但**人类入场排查前必须掌握对应侧的背景**（生产环境长什么样、数据在哪、谁能查监控）。本 skill 在长推理熔断交接 / 还原优先复盘 / 抛问题时按需加载，输出「侧别 + 判断依据 + 该侧人类需要什么背景」。
> **裁决链**：归 dev-loop 护栏 3，本 skill 零裁决权——只提供分流视角与背景清单。
> **人类侧说明书**：交接/还原/协作的人类视角完整指引（你会收到什么、该做什么、三条红线）→ 本目录 `manual.md`，向用户解释协作流程时直接指给它。

## 1. 八侧分类

| 侧 | 特征信号 | 典型例子 | 判断依据 |
|---|---|---|---|
| **代码侧** | 变更集相关；有报错或可复现 | 改错了；编译过但业务逻辑错；用了旧写法；修复引入新问题；隐性契约破坏 | `git diff <正常版本>..<故障快照>` 能对上 |
| **数据侧** | 代码无辜，**存量数据**是坏的 | 脏数据、迁移半途、schema 演进后旧记录不兼容、缓存过期格式 | 只在特定用户/特定老数据上触发；diff 查不出 |
| **环境侧** | 同一代码不同环境行为不同 | 依赖版本变了、上游接口变了、配置/开关漂移、本地无法复现 | 变更集无关 + 环境差异可指向 |
| **时序侧** | 不可复现/间歇性 | 竞态、缓存击穿、请求合并、顺序依赖 | 单测全绿、组合才错；需运行时证据 |
| **第三方侧** | 我方变更全无关，错误来自外部响应 | 上游风控封禁、Cookie/密钥/证书过期、配额用尽、对方悄悄改协议 | 集体突然失败；外部返回 403/429/封禁文案等 |
| **资源侧** | 与负载相关、渐进恶化、重启缓解 | OOM、磁盘满、连接池耗尽、QPS 超限 | 间歇性但随流量涨；监控曲线异常 |
| **发布侧** | 「跑的不是你以为的代码」 | 部署失败半截、灰度不一致、CDN/镜像缓存旧制品、回滚不完整 | 「本地是好的」；线上行为与同 commit 不符 |
| **意图侧** | 实现/测试/逻辑全对，用户说「不是我要的」 | 需求理解偏差 | 技术手段全部验不出，**只能问人** |

- 分流是**粗判不是结论**：多侧可并存（如代码侧改动暴露了数据侧坏数据），`[待验证假设]` 每条标主侧即可。
- **意图侧特殊**：一旦怀疑，**立即确认**（歧义阻断），严禁进入排查流程——那不是排查能解决的。

## 2. 各侧人类排查者需要的背景

人类接手排查时，AI 按「假设所在侧」附上对应背景需求（即 `[需要用户]` 资源清单的分类依据）：

| 侧 | 人类需要掌握的背景 | 常见来源 |
|---|---|---|
| 代码侧 | 最近变更的业务动机、改动评审上下文 | devlog、PR/commit 说明、用户口述 |
| 数据侧 | 生产/预发数据的访问途径、schema 版本历史、受影响用户/记录范围 | DB 访问权限、迁移记录、用户提供的查询结果 |
| 环境侧 | 各环境（本地/测试/预发/生产）的实际配置与依赖版本、部署时间线、监控/告警数据；**复杂环境操作（生产变更/内网调试/需专用工具链的排查）可请人类协助直接执行**——AI 只给操作步骤与预期输出，不硬试不可达的环境 | 环境访问权限、监控平台、部署日志 |
| 时序侧 | 流量特征（高峰/QPS）、复现操作路径、运行时日志（AI 本地拿不到） | 生产日志（服务名+时间窗+关键标识）、用户操作复现步骤 |
| 第三方侧 | 上游平台状态、账号与配额面板、封禁/工单渠道 | 平台状态页、账号控制台、联系/工单记录 |
| 资源侧 | 监控指标（CPU/内存/磁盘/QPS 曲线）、容量告警与阈值 | 监控平台、容量告警记录 |
| 发布侧 | CI/CD 流水线状态、线上**实际**制品版本/commit、回滚记录 | 流水线平台、制品仓库、部署/回滚日志 |
| 意图侧 | 真实业务意图、验收标准、历史沟通上下文 | **只能问用户**，无替代来源 |

- **能自查的不外推**（对齐 dev-loop 护栏 3）：表中「常见来源」里 AI 本地可达的（仓内配置、devlog、commit）先自己查，查完仍缺的才列入资源申请。

## 3. 输出格式（嵌入交接，不独立成文）

分类结果**不单独成文**，直接增强 dev-loop 护栏 3 的交接格式：

- `[待验证假设]` 每条尾部附 `(代码侧|数据侧|环境侧|时序侧|意图侧|第三方侧|资源侧|发布侧)`；
- `[需要用户]` 按「待验证假设的侧别」从 §2 表取背景需求条目，具体到可直接执行。

示例：

```
[待验证假设]
- 缓存击穿导致间歇 503（时序侧：需高峰时段运行时日志证实）
- 迁移半途旧记录格式不兼容（数据侧：需查受影响用户的存量记录）
[需要用户]
- 生产日志：rss-service 最近 2h，level≥warn，trace 前缀 `rss-`
- 预发 DB 只读账号（查 user_settings 表 schema_version 分布）
```

## 4. 边界

- 只服务**长排查/重大故障**场景（dev-loop 护栏 3 入口）；日常小修、散修不加载。
- 不定义修复流程（归 dev-loop §2 / 还原优先分支）；不落长期容器——分类判断是易失工作产物，排查结论的持久化走 devlog/Lesson 既有通道。
