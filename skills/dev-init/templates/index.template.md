# <repo> · 功能落点索引（规约）

> **索引数据 = `<index 数据路径>`**（索引/规范数据住 docs/project/，skill 只放规约）。索引机制（表格式规范、增量登记纪律）见全局 `project-index` skill，本文件不复制其正文。

## 1. 索引构成

`<index 数据路径>` 登记三张表，各有专属维护协议：

| 表 | 内容 | 何时登记 / 更新 |
|---|---|---|
| **代码落点** | 功能 → 代码落点 + 备注（关键单测 / 设计稿 / 注入位等指针） | 新功能落地、搬迁、改名后同轮登记 |
| **文档落点** | 主题 → 文档路径 + 状态 | 新增 / 移动 / 废弃 docs/ 文档时（与 docs/README.md、`<repo>-docs` 域表三处同步） |
| **架构债与依赖违例登记** | # → 债 → 落点 → 状态（活跃表）+ 已结项归档区 | 架构盘点 / 护栏命中后**先登记再动手**；每清零一项同轮**结项归档**（§2），活跃表只留未结项 |

<跨仓接缝/外部契约如有：SSOT = <外部路径>（跨仓只读），实现 = <本仓落点>——指针由代码落点表承担，本索引不复制契约语义（防双源）>

## 2. 登记纪律

- **增量登记，禁止一次性铺满**：表随实现长出来，不为「完整」预写空泛行。
- **一行一功能**：功能名可读（勿写任务号）；落点精确到文件（仓库相对路径，禁绝对路径）；备注只放定位后必读的指针（测试、SSOT 文档、注入位、红线）。
- **禁写施工过程**：日期、切片/步号、PR 交付记录、重构心路一律不进备注——过程事实归 Git log 与 `context/epics/`；备注单格以「指针 + 一句话红线」为上限。
- **禁留路径墓碑**：路径已不存在时直接删除该指针（Git 历史可溯）。
- **禁写易腐数字**：即时行数、计数等每次提交都会漂移的数字不入表；超标清单只登记「文件名 + 治理策略」，是否超标以当次扫描为准。
- **失效落点即修**：发现表中路径不存在 / 语义过期，同轮修正或删除，不留「待对账」。
- **结项归档（活跃表只减不增）**：架构债清零后，该行移入归档区，压缩为一行「#N 摘要 → 落点 → 结项日期」；过程细节归 Git log / epic devlog，不在索引复述。

## 3. 维护协议

- **散修须先登记再动手**：不在架构债表内的跨域改动，先在债表加行（或确认属 standards 允许方向）再写代码。
- **架构债清零三处同步**：① `<index 数据路径>` 债表结项归档；② `<standards 路径>`（如涉红灯规则增删）；③ 设计稿 / epic todos。
- **文档落点三处同步**：`<index 数据路径>` 文档落点表 + `docs/README.md` + `<repo>-docs` skill 域表。
- **命令速查不进本索引**：命令与环境事实源 = `<repo>-workflow` skill。
- **索引体检（防慢性腐化）**：索引腐化是单次登记都不违规、累积后显形的过程——epic 收尾（`::done`）或重大重构后对账一次：① 落点路径存在性抽查；② 活跃债表/归档区比例（活跃表只留未结项）；③ 超标清单与实际扫描对照。发现漂移同轮修正。
