# Skill: Memo-Collector (备忘收集 — 待办列表 + 完成列表)

> **定位声明**：与 dev-loop 互补——`memory.md` 的断点只记唯一「下一步」，本 skill 维护**多条目积压台账**：待办列表（todos.md）+ 完成列表（done.md）。组织对齐 dev-loop 挂靠模型：域内条目挂活跃 epic，散修/跨域挂 misc（与 devlog 挂靠同一套判定，规则只有一份）。不改动 dev-loop 任何流程，仅提供数据文件供其引用（/next 规划候选可取自待办列表）。

## 0. 文件落点与格式 (Layout & Format)

统一落**当前项目根**的 `context/`（复用 dev-loop 目录约定，随 git 提交；跨项目各自一份，不共享）。文件采用 **lessons.md 模式（全局单文件 + 分节）而非 memory 模式（每 epic 一文件）**：todos 的主消费场景是全局积压一览与低频检索，不存在 memory 那种「每会话恢复必读」的成本压力。`context/` 不存在时先建目录再写文件，**无需绑定 epic**；文件缺失时先用 write_file 落完整模板。

**`context/todos.md`（待办列表，SSOT，按域分节）**：

```markdown
---
memo: todos
format: v2
---

# 待办列表

## misc
```

- **节 = 域**：每个活跃 epic 一节（/bind 时**不预建节**，首次收集到该域条目时才建）；`## misc` 固定最后一节（常驻散修兜底，永不删除）。
- **条目行格式（写死）**：`- [ ] [YYYY-MM-DD] (<类型>) [(block)] <一句话事项> (src: ai | 用户)`——`(block)` 为可选后缀标签（紧随类型，仅可执行类型可挂），表达「阻塞本节 epic 主线」；**严禁扩展依赖图**（无 blocked-by / 多级优先级）。
- **类型内联标签（固定七种）**：功能 / 修复 / 优化 / 文档 / 环境 / 测试 / 风险。前六种为可执行待办（`测试` 专收测试用例与验证场景类待办：补单测、异常路径覆盖、回归/集成验证）；`风险` 兼收纯备忘（无动作但需记住的注意点/约束/坑）。归类就近落座，**严禁自造第八种**。
- **新建 epic 节**：Edit 锚定 `## misc` 行，在其上方插入 `## <epic名>` 节；新条目插到对应节标题行之后（节内最新在上）。

**`context/done.md`（完成列表，append-only，全局单文件）**：

```markdown
---
memo: done
format: v2
---

# 完成列表
```

条目行格式（写死）：`- [YYYY-MM-DD] <一句话事项> (域: <epic名 | misc>)`（唯一允许的追加后缀：`（人工打勾回收）`）

**v1 迁移**：若存在 format: v1 旧文件（六类型分节），迁移时全部条目并入 `## misc` 节（补内联类型标签），删除类型节标题，头部改 `format: v2`。

## 1. 自动收集协议 (触发点批量落盘)

**严禁逐轮碎写**（耗时 + git 噪音）：收集只在以下触发点批量落盘，其余轮次仅对话内暂记、不写文件：

1. **子任务收尾轮**：产生 Diff 落盘 / 子任务完结的轮次，收尾时一并自查——本轮回复与本窗口用户口述中的新备忘条目（含此前暂记的）；
2. **显式搁置决策**：排错/重构中决定「先记下来以后再修」的当轮；
3. **用户显式指令**：/todo 或「记个待办/收集备忘」。

暂记条目不出现在 /todos 视图；重置前未达触发点的暂记视同放弃——重要决策勿依赖备忘（走 /remember），窗口内随时可「收集一下刚才的备忘」回溯兑底。触发点命中后按表判定：

| 类型 | 判定特征 | 去向 |
|---|---|---|
| 待办 | 可执行的后续动作：建议做X / 后续需补Y / 已知待修Z / 用户口述「要加/要改/记得做」 | todos.md，类型标签 + 域归属见下 |
| 备忘 | 无动作但需记住：注意事项 / 风险 / 约束 / 坑 / 未验证假设（AI 顺嘴的「假设 X 已…」式前提；已含核对动作的按可执行 `(风险)` 落） | todos.md `(风险)` 标签 + 域归属见下 |
| 咒语 | 用户重复纠正的项目级约束/元知识（如「必须 Jakarta 不能 javax」「useEffect 必须加清理函数」）——驾驭当前技术栈的护栏素材 | **不落 todos**：当轮一行附注建议写入对应 SKILL.md 护栏，经用户确认后执行 |
| 完成 | 待办列表已有条目在本轮被完成；或用户口述「X 已完成，记一下」 | 移入 done.md（§2） |

**域归属判定（与 devlog 挂靠同规则）**：条目属当前绑定 epic 的域内工作 → 该 epic 节；跨域、无明确归属、散修杂项 → `## misc`；无法判定时一律 misc（常驻兜底）。CURRENT 为 none/未绑定时也一律 misc。

**实现口径（写死）**：
- **去重**：追加前 `grep -c '<关键词>' context/todos.md` 机械判重 + 对照目标节内容语义判重（同义改写/马甲条目视为重复），任一命中即跳过；
- **todos.md 追加**：Edit 锚定对应节标题行插入（§0 口径），禁止整读重写；写入后 `grep -c` 校验条目存在；
- **done.md 追加**：终端 `cat >> context/done.md <<'EOF'` 末尾追加（终端不可用时降级 Edit 锚定末条目行）；
- **极简附注**：收集发生时回复末尾附注一行，无收集则完全静默：

> 📥 已收集 N 条备忘 → `context/todos.md`（<epic名>×1、misc×1）

**豁免（不收集）**：
- 当前轮内立即执行的临时动作（「我这就改X」不收，做完也不收——devlog/memory 已覆盖）；
- 协议维护轮：/merge、/audit、/todos 查看等操作自身的写入；
- 与现有条目重复或仅措辞不同的项；
- **顺嘴提议/愿景类不收**：无明确触发条件与可核对产出的「以后可以考虑X」（许愿池）一律不收；拿不准的边缘条目 → 回复末尾一句询问（「另有 N 条边缘提议，入待办吗？」），确认后才落盘；
- 纯闲聊/未产生任何可留存结论的轮次。

**回溯收集**：用户要求「收集一下刚才的备忘」时，扫描本窗口全部 AI 回复与用户消息，按上表提取、去重后批量落盘，附注汇总。

## 2. 完成流转协议

- **调阅前回收（脏读校验）**：任何读取 todos.md 的场合（触发点收集 / /next 候选推导 / 指令调阅）第一步 `grep -ci '\- \[x\]' context/todos.md`；发现人工打勾条目（`[x]`/`[X]`）→ 逐条移入 done.md（行尾加 `（人工打勾回收）`）并从 todos.md 删除，附注一行「♻️ 已回收 N 条人工打勾项」后再继续；无则静默。
- 轮内工作完成待办列表中的某条目 → **自动流转，无需确认**：Edit 从 todos.md 删除该行（删除后 `grep -c` 校验该行为 0）+ 按 §1 口径追加一行至 done.md（记来源域），回复末尾附注：

> ✅ 已完成 N 条 → `context/done.md`

- 用户口述的完成事项（不在列表中）→ 仅当用户明确说「记到完成列表」才补记 done.md，严禁自动扩散（devlog/memory 已覆盖常规完成记录）；
- 条目过期不再相关 → 不自动删除；用户显式要求时整行删除（批量清空属破坏性操作，先列影响再确认）。

## 3. 指令面 (仅用户显式触发)

| 指令 | 职责 | 口径 |
|---|---|---|
| `/todo <事项>` | 追加待办 | 按 §1 域归属判定落节；用户口述视为已确认，无需二次询问 |
| `/todos [域]` | 只读展示待办 | 默认全量（带临时编号 `#1 #2…`）；可按域过滤；无条目则回「待办列表为空」 |
| `/tdone <编号\|关键词>` | 完成流转 | 按 §2 移入 done.md；关键词歧义时列候选让用户选 |
| `/todo-clean` | 清理待办 | 列出全量条目 → 用户勾选要删的 → 批量删除（需确认） |
| `/todo-groom` | 语义洗盘 | 全量审视：合并语义同类项（保留信息量大的一条，注明「并入自 X」）直接执行；疑似过期/已完成项列出经确认后删；任一节 >10 条时在触发点附注建议 |

## 4. 护栏

- **epic 收尾联动**：`/done <epic>` 收尾时该 epic 节必须清零——条目逐条处置（完成→done.md / 转 misc / 删除，经用户确认），随后删除该节标题；misc 为常驻兜底，不随任何收尾清空。
- **分支纪律**：todos.md 随 git 提交（**严禁 gitignore**——移出版本控制是体系反模式）；切分支/切机器前先结算（可流转的流转，其余保留）并 commit；合并冲突以**行级并集**手工解决（待办条目无真语义冲突，保留双方条目、去重即可）。
- **[x] 通道单向**：AI 严禁写 `[x]`（AI 的完成 = 移出列表）；`[x]` 是人类专用手动通道，Agent 只负责回收（§2 脏读校验）。
- **防递归**：本 skill 自身的维护写入不触发任何日志（若 dev-loop 活跃，同样不记 devlog）。
- **防膨胀**：todos.md 总条目 >30 时附注建议清理；done.md 软阈值 300 行——达成后于下一次 /done 收尾轮顺手归档（`mv context/done.md context/archive/done-YYYYMM.md` + 新建空 done.md，archive 缺失先建，经用户确认；同月归档名已存在则并入既有文件），长期无 /done 且明显超阈值时，写 done.md 轮附注提醒一次。
- **防漂移**：条目必须一句话可执行/可核对，带日期、类型标签与来源；模糊条目（如「优化一下」）落盘前先与用户确认具体化。
- **极简附注**：一切附注单行，不打断正常回复流。

## 5. 与 dev-loop 对齐（候选池 / 执行台）

会话恢复照 dev-loop §3 走（CURRENT + memory.md）；todos.md 按域分节对齐 dev-loop 挂靠模型（epic 节 + misc 兑底，判定规则与 devlog 挂靠同源）。

**候选池 / 执行台原则**：todos.md 是 /next 的**候选池**，memory.md 断点是唯一**执行台**。/next 推导候选（dev-loop §6）时的取用优先级：

1. 当前 epic 节 `(block)` 条目——阻塞主线，绝对优先（先解阻塞，被阻塞的主线才有意义）；
2. memory.md 遗留断点（未过期则直接报告开工，不重排）；
3. 当前 epic 节 `(修复)` 与可转化为具体动作的 `(风险)`；
4. 当前 epic 节 `(功能)` `(优化)` `(测试)`；
5. `## misc` 节。

- TODO 被选定开工时：经 dev-loop §6 既有口径落盘为断点（执行台唯一写入路径），todos.md 中保持 `[ ]` 不变——条目状态只在完成流转（§2）时离开列表，**严禁维护「进行中」双状态**；
- memo-collector 自身严禁直写 memory.md；断点刷新属 dev-loop 职责。
