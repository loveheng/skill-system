# Skill: Memo-Collector (备忘收集 — 待办列表 + 完成列表)

> **定位声明**：与 dev-loop 互补——`memory.md` 的断点只记唯一「下一步」，本 skill 维护**多条目积压台账**：待办列表（域内 todos.md + 全局 todos.md）+ 完成列表（done.md）。组织与 devlog **完全同构**（目录挂靠，判定规则只有一份）：域内条目落 `context/epics/<名>/todos.md`，散修/跨域/项目级落全局 `context/todos.md` 的 `## misc` 兜底节。不改动 dev-loop 任何流程，仅提供数据文件供其引用（::next 规划候选可取自待办列表）。

## 0. 文件落点与格式 (Layout & Format)

统一落**当前项目根**的 `context/`（复用 dev-loop 目录约定，随 git 提交；跨项目各自一份，不共享）。落点为**两级模型（2026-10-07 ::adr 裁定，见各项目 decisions.md misc 节口径）**：域内文件随 epic 目录（与 devlog 同构——::next 候选/恢复/收尾清零只读本域文件），全局文件只兜底非域内条目；「全局积压一览」由 `toolbox run todos list` 机械聚合，不靠单文件。台账读写**一律走 `toolbox run todos`**（add/done/rm/move/list，AI 零手搓），脚本缺失时才降级 Edit 手工（禁整读重写）；`context/` 不存在时先建目录再写文件，**无需绑定 epic**。

**`context/todos.md`（全局兜底台账：misc 散修 / 跨域 / 项目级）**：

```markdown
---
memo: todos
format: v3
---

# 待办列表

## misc
```

- **全局文件只此一节**：`## misc` 恒为唯一节且永不删除（散修兜底 + 跨域 `(风险)`/`(block)` + 项目级/系统级事项 + S3 PATCH 债 + 副作用高危转化）。epic 节模型已退役（存量 epic 节条目按 v3 域级迁移归各域文件）。

**`context/epics/<名>/todos.md`（域内待办，按需创建，随 epic 归档）**：

```markdown
---
memo: todos
format: v3
epic: <名>
---

# <名> · 域内待办
```

- **按需创建**：epic 绑定/挂载时**不预建**（mount-init 不生成空骨架），首条域内条目落盘时由 `todos add` 创建；条目直接追加在标题行之后（域内最新在上），**域文件无分节**。
- **条目行格式（写死）**：`- [ ] [YYYY-MM-DD] (<类型>) [once|long]? [(block)]? [(状态)]? (层:L0-L4)? (重:轻/中/重)? <一句话事项> (src: ai | 用户[, <来源工具>])`——标签顺序固定：类型 → 生命周期标注 → `(block)` → `(状态)` → `(层:Ln)` → `(重:X)`；`(block)` / `(状态)` / `(层:Ln)` / `(重:X)` 均为可选元数据（轻量项目可省略，缺省即 v2 兼容）。`(状态)` 为结构化状态（见下，禁用 emoji）；`(层:Ln)` 技术层次、`(重:X)` 工作量权重，用于跨项目排序与 `::todo-groom` 筛选。
- **生命周期标注（与类型正交，可选）**：`[once]` / `[long]`，紧随类型标签之后（在 `(block)` 之前）——仅对**有时效/事件绑定**的事项标注，普通积压项不标（默认普通流转）：
  - `[once]` 一次性：事件/时效绑定的后续动作（「部署后 24h 盯队列深度」「跑一次回填」）。判定特征：事项含一次性触发条件或明确时限。处置：事件确认完成（用户明示或本窗口执行并验证）→ 按 §2 自动流转 done.md；::audit 发现 30 天未动且已过事件窗口 → 附注建议过期清除（防 todos 变噪音坟场）；确认失效不做 → 整行删除（附注原因，不入 done.md）；
  - `[long]` 长期：跨里程碑持续有效（容量/架构/需随增长重评）。判定特征：事项含「重评/到 X 时/随增长/长期」。处置：留存不动，**每个 `::done` 收尾强制逐条重评**（保留/转具体动作/关闭，经确认）。
- **类型内联标签（固定七种）**：功能 / 修复 / 优化 / 文档 / 环境 / 测试 / 风险。前六种为可执行待办（`测试` 专收测试用例与验证场景类待办：补单测、异常路径覆盖、回归/集成验证）；`风险` 兼收纯备忘（无动作但需记住的注意点/约束/坑）。归类就近落座，**严禁自造第八种**。
- **结构化状态 `(状态)`（与类型/生命周期正交，可选）**：`降级` / `暂缓` / `候`，**禁用 emoji**（如 🅿）。`降级`=主线拍板后置/降优先级；`暂缓`=用户拍板暂缓、待真机反馈再排期；`候`=实现候选项、依附其他项动工时一并做、勿单独排期。机器可解析，供 `::todo-groom` 筛选与跨项目聚合。
- **分层 / 权重元数据（可选，跨项目排序用）**：`(层:L0-L4)` 技术层次——L0 引擎算法 / L1 平台系统 / L2 数据存储 / L3 加工管线 / L4 UI 交互；`(重:轻/中/重)` 工作量——轻(1-2文件局部) / 中(单模块改造) / 重(跨模块·新页·架构)。二者均可选；散修 misc 项或轻量项目可省略，仅主线/评审场景补以增强可排序性。
- **路由规则（写死，判定先于落盘）**：① **域内**——该 epic 可独立解决的行动项（拆解跟进、子任务、域内修复/测试项）→ `todos add --to <epic名>`；② **全局**——跨域 `(风险)`/`(block)`、项目级/系统级事项、S3 PATCH 债（solution-admission §3）、副作用高危转化（ai-sideeffect-guard §4）、无明确归属 → `todos add --to misc`；③ 拿不准一律 misc（常驻兜底）；CURRENT 为 none/未绑定时一律 misc。**防双写**：大任务的拆解结构与理由落挂载文档（blueprint），域文件只收一行式行动项。

**`context/done.md`（完成列表，append-only，全局单文件）**：

```markdown
---
memo: done
format: v2
---

# 完成列表
```

条目行格式（写死）：`- [YYYY-MM-DD] <一句话事项> (域: <epic名 | misc>)`（唯一允许的追加后缀：`（人工打勾回收）`）

**v1 迁移**：若存在 format: v1 旧文件（六类型分节），迁移时全部条目并入 `## misc` 节（补内联类型标签），删除类型节标题，头部改 `format: v2`。

**v2→v3 迁移**：todos.md 头部 `format: v2` → `v3`；条目行在类型后可选追加 `(状态)`（降级/暂缓/候，替换任何手写 emoji 状态）、`(层:L0-L4)`、`(重:轻/中/重)` 元数据（均向后兼容，旧条目缺省即等同 v2，无需强制补全）；done.md 维持 v2 不变。

**v3 域级迁移（2026-10-07，一次性）**：全局文件中各 epic 节的条目整节迁往 `context/epics/<名>/todos.md`（`todos add` 补域文件头部，条目行内容原样保留；非标准手搓节并入语义对应域）；全局文件重建为仅 `## misc` 节；done.md 历史不动。

## 1. 自动收集协议 (触发点批量落盘)

**严禁逐轮碎写**（耗时 + git 噪音）：收集只在以下触发点批量落盘，其余轮次仅对话内暂记、不写文件：

1. **子任务收尾轮**：产生 Diff 落盘 / 子任务完结的轮次，收尾时一并自查——本轮回复与本窗口用户口述中的新备忘条目（含此前暂记的）；
2. **结论性问答轮**：无 Diff 但回答含**方案对比/被否决项/注意事项/风险/未验证假设/事实发现/待办信号**的咨询轮，收尾时按判定表批量落盘（问答的结论产出同样蒸发，不豁免）；
3. **显式搁置决策**：排错/重构中决定「先记下来以后再修」的当轮；
4. **用户显式指令**：::todo 或「记个待办/收集备忘」。

暂记条目不出现在 ::todos 视图；重置前未达触发点的暂记视同放弃——重要决策勿依赖备忘（走 ::remember），窗口内随时可「收集一下刚才的备忘」回溯兑底。触发点命中后按表判定：

| 类型 | 判定特征 | 去向 |
|---|---|---|
| 待办 | 可执行的后续动作：建议做X / 后续需补Y / 已知待修Z / 用户口述「要加/要改/记得做」 | todos.md，类型标签 + 域归属见下 + 生命周期标注（§0，有时效/事件绑定时判 `[once]`/`[long]`） |
| 备忘 | 无动作但需记住：注意事项 / 风险 / 约束 / 坑 / 未验证假设（AI 顺嘴的「假设 X 已…」式前提；已含核对动作的按可执行 `(风险)` 落） | todos.md `(风险)` 标签 + 域归属见下 + 生命周期标注同上（风险类最常带 `[long]`：需重评的隐患；事件绑定的盯守动作带 `[once]`） |
| 咒语 | 用户重复纠正的项目级约束/元知识（如「必须 Jakarta 不能 javax」「useEffect 必须加清理函数」）——驾驭当前技术栈的护栏素材；**AI 被迫向用户澄清的环境约束/惯例同属此类**（用户的回答是待固化事实，澄清过的问题不应再问第二次） | **不落 todos**：当轮一行附注建议写入对应 SKILL.md 护栏，经用户确认后执行；**同类澄清 ≥2 次** = 固化信号——附注提议升级到事实源（workflow skill / 索引别名映射 / 规范 skill），经确认落位；**方案级权衡**（本轮 AI 给出多方案对比且用户已选定）同轮附注一句「建议 ::adr 记档」，经确认走 dev-loop §6 落 decisions.md；**全局级**（跨项目交互偏好/约定）→ 附注建议写 `~/.agents/AGENTS.md`（全局指令 SSOT，同步副本 `~/.zcode/AGENTS.md`），经确认落位 |
| 事实 | 交互中发现的**项目事实/机制真相**（非待办非风险非咒语：「原来 X 的行为是 Y」「该接口有隐藏参数 Z」）——后续轮次的判断素材 | **不落 todos**：当轮一行附注建议落事实源——项目级 → 挂载文档 / 项目索引 / workflow 事实源 skill，经确认落位（对齐 dev-loop §7 第 10 项「事实指针化」的反向通道：事实进事实源，不进会话蒸发区） |
| 完成 | 待办列表已有条目在本轮被完成；或用户口述「X 已完成，记一下」 | 移入 done.md（§2） |

**域归属判定（§0 路由规则，与 devlog 挂靠同规则）**：条目属当前绑定 epic 的域内工作 → 该 epic 域文件（`todos add --to <epic名>`）；跨域、无明确归属、散修杂项 → 全局（`todos add --to misc`）；无法判定时一律 misc（常驻兜底）。CURRENT 为 none/未绑定时也一律 misc。

**实现口径（写死）**：
- **去重**：`todos add` 自动同文提醒 + 对照目标落点内容语义判重（同义改写/马甲条目视为重复），命中即跳过；
- **todos 追加**：一律 `toolbox run todos add --to <epic名|misc> [--type ...] [--block] ...`（脚本缺失时降级 Edit 锚定插入，禁整读重写）；写入后 `todos list` 或 grep 校验条目存在；
- **done 流转**：一律 `toolbox run todos done <关键词>`（自动删除源条目 + 追加 done.md 记来源域；脚本缺失时降级 Edit 双写并核对）；
- **极简附注**：收集发生时回复末尾附注一行，无收集则完全静默：

> 📥 已收集 N 条备忘 → `context/todos.md`（<epic名>×1、misc×1）

**豁免（不收集）**：
- 当前轮内立即执行的临时动作（「我这就改X」不收，做完也不收——devlog/memory 已覆盖）；
- 协议维护轮：::merge、::audit、::todos 查看等操作自身的写入；
- 与现有条目重复或仅措辞不同的项；
- **顺嘴提议/愿景类不收**：无明确触发条件与可核对产出的「以后可以考虑X」（许愿池）一律不收；拿不准的边缘条目 → 回复末尾一句询问（「另有 N 条边缘提议，入待办吗？」），确认后才落盘；
- 纯闲聊/未产生任何可留存结论的轮次。

**回溯收集**：用户要求「收集一下刚才的备忘」时，扫描本窗口全部 AI 回复与用户消息，按上表提取、去重后批量落盘，附注汇总。

## 2. 完成流转协议

- **调阅前回收（脏读校验）**：任何读取待办台账的场合（触发点收集 / ::next 候选推导 / 指令调阅）第一步扫人工打勾条目（`[x]`/`[X]`——全局与域文件都要扫，`grep -rc '\- \[x\]' <项目>/context/`）→ 逐条移入 done.md（行尾加 `（人工打勾回收）`）并从来源文件删除，附注一行「♻️ 已回收 N 条人工打勾项」后再继续；无则静默。
- 轮内工作完成待办列表中的某条目 → **自动流转，无需确认**：`toolbox run todos done <关键词>`（自动删除源条目 + 追加 done.md 记来源域），回复末尾附注：

> ✅ 已完成 N 条 → `context/done.md`

- 用户口述的完成事项（不在列表中）→ 仅当用户明确说「记到完成列表」才补记 done.md，严禁自动扩散（devlog/memory 已覆盖常规完成记录）；
- **`[once]` 完成流转**：该一次性事件在本窗口被确认完成（用户明示「X 盯过了/做完了」或 AI 执行并验证）→ 按上行口径**自动流转** done.md，无需确认；事件确认失效不做 → 整行删除并附注原因（不流转 done.md）；
- 条目过期不再相关 → 不自动删除；用户显式要求时整行删除（批量清空属破坏性操作，先列影响再确认）。

## 3. 指令面 (仅用户显式触发)

| 指令 | 职责 | 口径 |
|---|---|---|
| `::todo <事项>` | 追加待办 | 按 §0 路由规则判域 → `todos add --to <epic名\|misc>` 落盘；用户口述视为已确认，无需二次询问 |
| `::todos [域]` | 只读展示待办 | `todos list [名\|all]` 机械聚合（默认全量带临时编号 `#1 #2…`，全局与域文件并列）；无条目则回「待办列表为空」 |
| `::tdone <编号\|关键词>` | 完成流转 | `todos done <关键词>` 移入 done.md；关键词歧义时列候选让用户选 |
| `::todo-clean` | 清理待办 | 列出全量条目 → 用户勾选要删的 → 逐条 `todos rm`（需确认，破坏性） |
| `::todo-groom` | 语义洗盘 | 全量审视（`todos list all`）：合并语义同类项（保留信息量大的一条，注明「并入自 X」）直接执行（rm+add）；疑似过期/已完成项列出经确认后删；任一文件 >10 条时在触发点附注建议 |

## 4. 护栏

- **epic 收尾联动**：epic 经 `::done` 收尾时（`::done` 作用于当前绑定 epic，无独立参数）该 epic 域文件必须清零——条目逐条处置（完成→`todos done` / 转全局→`todos move --to misc` / 删除→`todos rm`，经用户确认），随后删除 `epics/<名>/todos.md`（随 epic 目录归档）；全局 `## misc` 为常驻兜底，不随任何收尾清空。**全量 `[long]` 条目（全局+域文件）随 ::done 强制重评**（保留 / 转具体动作 / 关闭，逐条经确认）；`[once]` 条目收尾时已过事件窗口的列出让用户确认清除或补做。
- **分支纪律**：todos.md 随 git 提交（**严禁 gitignore**——移出版本控制是体系反模式）；切分支/切机器前先结算（可流转的流转，其余保留）并 commit；合并冲突以**行级并集**手工解决（待办条目无真语义冲突，保留双方条目、去重即可）。
- **[x] 通道单向**：AI 严禁写 `[x]`（AI 的完成 = 移出列表）；`[x]` 是人类专用手动通道，Agent 只负责回收（§2 脏读校验）。
- **防递归**：本 skill 自身的维护写入不触发任何日志（若 dev-loop 活跃，同样不记 devlog）。
- **防膨胀**：待办总量（全局+域文件聚合，`todos list all` 合计数）>30 时附注建议清理，单文件 >10 条同样附注；done.md 软阈值 300 行——达成后于下一次 ::done 收尾轮顺手归档（`mv context/done.md context/archive/done-YYYYMM.md` + 新建空 done.md，archive 缺失先建，经用户确认；同月归档名已存在则并入既有文件），长期无 ::done 且明显超阈值时，写 done.md 轮附注提醒一次。
- **防漂移**：条目必须一句话可执行/可核对，带日期、类型标签与来源；模糊条目（如「优化一下」）落盘前先与用户确认具体化。
- **极简附注**：一切附注单行，不打断正常回复流。
